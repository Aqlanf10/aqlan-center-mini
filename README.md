# انسياب العيادة — مركز الدكتور عقلان الكامل

شاشة واحدة تقول ثلاثة أرقام لا يعرفها أحد في العيادة الآن: **كم مريضًا ينتظر، ومنذ متى،
وهل الكرسي فارغ.**

## لماذا هذه الأداة موجودة

النظام الأساسي يملك قائمة انتظار وشاشة نداء وفحص تعارض مواعيد وجداول أطباء — ولم يدخل
الخدمة بعد. وفي الأثناء، المرضى ينتظرون ساعات ولا أحد يرى الرقم. هذه أداة مؤقتة مهمتها
واحدة: أن تُستخدم **صباح الغد**، لا أن تكون كاملة.

لذلك هي شاشة واحدة بلا إعدادات ولا تدريب: اكتب اسمًا واضغط «وصل»، ثم اضغط رقم الكرسي.

## قاعدة بيانات مستقلة — قرار مقصود

لا تكتب هذه الأداة في قاعدة النظام الأساسي إطلاقًا. قواعد المال ومسار الزيارة والأقفال
كلها في واجهة النظام الأساسي، وأي كتابة مباشرة من برنامج ثانٍ كانت ستُفسد أرقامه بصمت.
الثمن المقبول: بيانات هذه الأداة تُرحَّل لاحقًا حين يدخل النظام الأساسي الخدمة.

## الإعدادات `/settings` — لا قيمة مكتوبة في الكود

اسم المركز والطبيب والمؤهل والهاتف والعنوان · **أسعار صرف الريال السعودي والدولار** ·
عدد الكراسي · ساعات الدوام · مهلة المختبر · مدة اعتبار المريض منقطعًا — كلها من شاشة
واحدة للمدير وحده. عدد الكراسي صار ثلاثة؟ سعر الصرف تغيّر اليوم؟ دقيقة من الشاشة، لا
نشرة برمجية.

- التعديل **للمدير وحده**: سعر صرف خاطئ يفسد كل تقرير بعده، وعدد كراسٍ خاطئ يفسد كل
  حجز.
- قيمة تالفة في الجدول لا تُعطّل شيئًا: تُردّ إلى حدودها المنطقية عند القراءة.
- الصفحات العامة (`/display` و`/book`) ترى **المسموح وحده** — اسم المركز وهاتفه وعدد
  الكراسي. القائمة مسموح لا ممنوع، فمفتاحٌ يُضاف غدًا يكون محجوبًا تلقائيًا.
- **سعر الصرف يُستخدم للدفعات الجديدة فقط.** كل دفعة سابقة تحتفظ بسعر يومها ولا
  يتغيّر أثرها في التقارير حين يُحدَّث السعر.

## التشغيل على Railway

منصة واحدة للتطبيق وقاعدة البيانات معًا — **وهذا هو سبب الاختيار لا صدفةً فيه**: كل
شاشة في البرنامج ديناميكية وتقرأ من القاعدة في كل طلب، ولوحة الانتظار تُحدَّث كل
ثوانٍ. فبقاء التطبيق والقاعدة في شبكة واحدة يجعل رحلة الاستعلام داخلية بدل أن تقطع
الإنترنت مرتين عند كل نداء مريض — والفرق يُحسّ في الزحمة، وهي المشكلة الأولى في المركز.

> **حدّ عزل إلزامي:** هذا الفرع يعمل داخل مشروع Railway الخاص بـ`aqlan-center-mini`
> فقط، لكنه يستخدم قاعدة مخصصة باسم `aqlan_center_mini_v2` داخل خدمة PostgreSQL
> التابعة للمشروع. قاعدة `railway` القديمة تبقى دون تعديل للرجوع، وقاعدة برنامج
> `aqlan-center` الآخر لا تُستخدم إطلاقًا. يحوّل الخادم `DATABASE_URL` داخليًا إلى
> الاسم المخصص ويرفض الاتصال إذا شُغّل داخل مشروع Railway مختلف. لا يُنسخ رابط فعلي
> أو كلمة مرور إلى Git.

**البناء بـDockerfile لا بكاشف المنصة التلقائي.** الكاشف يخمّن إصدار Node وأمر
البناء، ويتغيّر تخمينه بترقية المنصة. وبناءٌ يتغيّر وحده تحت عيادة تعمل ليس بناءً.

1. مشروع جديد على Railway ← أضف `PostgreSQL`.
2. أضف خدمة من مستودع GitHub — يلتقط `railway.json` و`Dockerfile` تلقائيًا.
3. متغيّرات البيئة على خدمة الويب:

   | المتغيّر | القيمة |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` — مرجعٌ لا نسخة، فلا يتعطّل التطبيق إن دُوِّرت كلمة سر القاعدة |
   | `CLINIC_TIME_ZONE` | `Asia/Aden` |
   | `SESSION_SECRET` | ‏32 حرفًا فأكثر: `openssl rand -base64 48` |
   | `SETUP_TOKEN` | ‏16 حرفًا فأكثر — **لإنشاء أول حساب فقط، ثم يُحذف** |

4. انشر. الجداول تُنشأ تلقائيًا عند أول فتح — لا خطوة هجرات.
5. افتح `/setup` وأنشئ حساب المدير، ثم **احذف `SETUP_TOKEN`** من المتغيّرات.

في أول تجهيز للفرع داخل مشروع `aqlan-center-mini` شغّل مرة واحدة:

```bash
npm run db:provision:mini
```

ينشئ الأمر قاعدة `aqlan_center_mini_v2` إن لم تكن موجودة، ثم يبني مخطط Aqlan
Center فيها. الأمر يرفض العمل خارج مشروع Mini، ولا يحذف أو يغيّر قاعدة `railway`
القديمة.

**فحص الجاهزية:** `/api/ping` نبضٌ للمنصة لا يمسّ القاعدة — وهذا مقصود: لو مسّها
لصار انقطاعٌ عابر فيها حكمًا بالموت على خدمة سليمة، فتُعاد تشغيلها أو تُلغى نشرة
صحيحة في وقت الذروة. والتشخيص مكانه `/api/health`: يقول أيّ إعداد ناقص، ولا يكشف قيمة أيّ سرّ.

## النسخ الاحتياطي — من داخل البرنامج

**زرٌّ واحد**: `/settings/export` ← «نزّل النسخة الكاملة الآن». ملف واحد فيه كل مريض
وكل موعد وكل فاتورة وكل سند وكل قيد — ينزل إلى الجهاز مباشرة.

ولماذا لا `pg_dump`؟ لأن من يحتاج النسخة صاحب العيادة لا مهندس: `pg_dump` يعني تثبيت
أدوات وسطر أوامر ونسخ رابط قاعدة يحمل كلمة السر. **ونسخةٌ تحتاج كل ذلك لا تُؤخذ —
وأسوأ نسخة هي التي لم تُؤخذ.**

- **بيانات بلا مخطط**: البرنامج ينشئ جداوله بنفسه، فالاستعادة قاعدةٌ فارغة يفتحها
  البرنامج مرة فيبني جداولها، ثم يُشغَّل عليها الملف.
- **ترتيب الجداول من مفاتيح القاعدة نفسها** لا من قائمة مكتوبة بيد: القائمة اليدوية
  تنسى جدولًا يُضاف غدًا فتفشل الاستعادة بخطأ مفتاح أجنبي في أسوأ لحظة.
- **بلا `TRUNCATE` ولا `DROP` عمدًا.** ملفٌّ يمسح قبل أن يكتب يبدو أذكى، لكنه يعني أن
  نقرة خاطئة على قاعدة تعمل تمحو يوم عمل. فالاستعادة فوق بيانات موجودة **تفشل**
  باصطدام المفاتيح — وهو الفشل الصحيح.
- **العدّادات تُعاد ضبطها**: بلا ذلك تصطدم أول فاتورة جديدة برقم موجود — واستعادةٌ
  تبدو ناجحة ثم تنفجر عند أول عملية أسوأ من استعادة تفشل صراحةً.
- **انقطاعٌ أثناء التنزيل يُختم بسطر يُفشل الاستعادة**: الملف الناقص أخطر من غيابه،
  لأن من ينزّله يظنّه نسخة.
- **للمدير وحده** — ولا للاستقبال: الملف يحمل الأرشيف كله.

```bash
npm run verify:backup   # نسخة ← قاعدة مؤقتة ← مقارنة كل جدول صفًّا بصف ← حذفها
npm run restore ملف.sql # الاستعادة على قاعدة فارغة
npm run verify:schema   # هل يُبنى المخطط من الصفر أصلًا؟
```

`verify:backup` هو الفحص الذي يهمّ فعلًا: **نسخةٌ تُؤخذ كل يوم ولا تُستعاد أسوأ من لا
نسخة** — الأولى تعطي طمأنينة كاذبة إلى يوم الكارثة.

وملفات CSV في الشاشة نفسها تكمّل ولا تغني: تُقرأ في Excel للمراجعة، ولا يُستعاد منها نظام.


## الفحوص

```bash
npm run typecheck   # TypeScript strict
npm test            # المنطق الخالص — بلا قاعدة ولا شبكة
npm run build
```

وفحوصٌ تعمل على قاعدةٍ حقيقية، لأن ما تفحصه سلوكُ القاعدة نفسها لا منطقُ الدوال:

```bash
npm run verify:schema        # هل يُبنى المخطط من الصفر أصلًا؟
npm run verify:backup        # نسخة ← قاعدة مؤقتة ← مقارنة كل جدول صفًّا بصف
npm run verify:concurrency   # ترقيم المستندات تحت التزامن — بلا فشل ولا تكرار
npm run verify:audit         # سجل التدقيق يرفض التعديل والحذف من اتصالٍ مباشر
npm run verify:clinical      # توقيعٌ واحد ← فاتورة ← مخطط، وكلها تسقط معًا
npm run verify:plans         # الخطة: اشتقاق الإجمالي، قفل الموافقة، شطبها بالزيارة
npm run verify:identity      # مريضٌ واحد بسجلٍّ واحد — ولا دمج بالاسم صامتًا
npm run verify:documents     # الأشعة على القرص لا في القاعدة، وأرشيفها يُفكّ بـ tar
npm run verify:ortho         # حالةٌ مفتوحة واحدة، وسلكٌ لا يفارق سجلّه
```

### الرحلات — ما لا تقوله الفحوص

الفحص يثبت المنطق، والرحلة تثبت أن **الشاشة توصّل إليه**. وبينهما وقع أكثر ما وقع
من خلل: زرٌّ لا يظهر، وحقلٌ لا يُحفظ، ومخططٌ يُعرض معكوسًا لأن RTL قلب صفّ الأسنان.

```bash
npm i -g playwright                 # ليست تبعية عمدًا — انظر أدناه
npm run journey:visit ./shots       # وصول ← كرسي ← توثيق ← توقيع ← كشف حساب
npm run journey:plan  ./shots       # خطة ← موافقة ← مخطط ← زيارة تشطب بندًا
npm run journey:identity ./shots    # مريضٌ مسجَّل يصل بلا رقم — بلا ملفٍّ ثانٍ
npm run journey:documents ./shots   # رفع أشعة ← عرضها ← أرشيفها
npm run journey:ortho ./shots       # حالة ← شدّات ← قراءة السلك على الكرسي
```

وليست Playwright تبعيةً في `package.json` عمدًا: إضافتها تجعل `npm ci` داخل Docker
يحاول تنزيل متصفّح عند كل بناء، فيبطؤ النشر أو يفشل بلا سبب ظاهر. والرحلات أدوات
تحقّقٍ تُشغَّل باليد على جهاز التطوير، لا جزءًا من الإنتاج.

## ما تفعله وما لا تفعله

**تفعل:** تسجيل وصول، قائمة انتظار مرتبة بالأطول انتظارًا، حالة الكرسيين، تنبيه حين
يكون هناك كرسي فارغ ومريض ينتظر، نداء المريض إلى كرسي مع شاشة صالة، مواعيد الجلسات
القادمة مع كشف التعارض، وتذكير واتساب قبل الموعد، وإنهاء الزيارة.

**لا تفعل — عمدًا في هذه المرحلة:** لا حجز مواعيد مستقبلية، ولا فواتير ولا مدفوعات.

## شاشة الصالة `/display`

تلفاز في صالة الانتظار يفتح `/display` ويُترك. الاستقبال تضغط «نادِ · كرسي ١» أمام اسم
المريض في اللوحة، فيظهر اسمه على الشاشة ويُصدر التلفاز نغمة.

- **الشاشة مفتوحة بلا تسجيل دخول** — عمدًا: التلفاز لا لوحة مفاتيح معه، والجلسة تنتهي
  بعد اثنتي عشرة ساعة، فربطها بها كان يعني شاشة سوداء كل صباح.
- ما يخرج من الخادم إلى تلك الصفحة مُقيّد بما يُعرض فقط: **الاسم الأول** ورقم الكرسي
  وعدد المنتظرين. لا هاتف ولا اسم كامل ولا رقم مريض ولا مُعرّف زيارة — الفلترة على
  الخادم لا في الواجهة، فلا تكشفها أدوات المتصفح.
- النغمة تحتاج ضغطة واحدة على «تشغيل صوت النداء» عند فتح الشاشة صباحًا (سياسة
  المتصفحات تمنع الصوت التلقائي).
- انقطاع الشبكة لا يُفرغ الشاشة: يبقى آخر ما وصل ويظهر مؤشّر «يُعاد الاتصال…».

**النداء يحجز الكرسي.** بين نداء المريض وجلوسه دقيقة يمشي فيها من الصالة، والكرسي
محسوب مشغولًا فيها فلا يُنادى إليه ثانٍ. ومن لم يسمع النداء يُعاد إلى الانتظار بزر «لم
يحضر» — بلا هذا الزر يبقى الكرسي محجوزًا له إلى آخر اليوم.

**الإعلانات المتناوبة سجلاتٌ لا خانة.** كانت تُكتب كلها في إعدادٍ نصّي واحد («العنوان |
النص» في كل سطر)، فاعترضها حدّ الإعداد الكلي عند العشرين إعلانًا برسالة «القيمة طويلة
أكثر من اللازم»، ولا سبيل فيها لتعطيل إعلانٍ واحد أو ترتيبه. الآن لكل إعلانٍ سجلّه في
جدول `display_announcements`: عنوان (≤ ٨٠ حرفًا) ونص (≤ ٣٠٠) وترتيب وتفعيل ومَن
عدّله آخرًا — يُدار من الإعدادات ← شاشة الصالة بقائمة حيّة: إضافة بزرٍّ واحد، وتعديل
وحذف (بتأكيد) لكل إعلانٍ وحده، وترتيب بالسحب أو الأسهم. والكتابة للمدير وحده
(الصلاحية في الخادم)، والشاشة العامة تقرأ `/api/display` فيرودها المفعّل وحده بترتيبه
عنوانًا ونصًّا لا أكثر. الإعلانات القديمة هُجِّرت مرةً واحدة تلقائيًا عند أول قراءة بعد
النشر (التحقق قبل مسح القيمة القديمة، وعلمٌ في `settings` يمنع التكرار)، وإن فشلت
الترحيلة عمل احتياط الصيغة القديمة فلا تتعطل الشاشة.

## الحجز الإلكتروني `/book` و`/requests`

المريض يفتح `/book` — صفحة عامة بلا تسجيل دخول — ويكتب اسمه ورقمه واليوم الذي يناسبه.
الاستقبال تفتح `/requests` فترى الطلبات **الأقدم أولًا**، تحدّد وقتًا، وتضغط «تأكيد
الحجز»، فيظهر زر واتساب برسالة تأكيد جاهزة.

**المريض يطلب ولا يحجز.** صفحة عامة تكتب في جدول المواعيد مباشرة تعني — في عيادة
بكرسيين — يومًا ممتلئًا بأسماء لا أحد يعرف إن كانت حقيقية. ولذلك الرد على المريض بعد
الإرسال يقول «وصلنا طلبكم وسنتصل بكم» لا «تم الحجز»: مريضٌ جاء ظانًّا أن له موعدًا ثم
لم يجده هو نفس شكوى الإهمال التي بُنيت الأداة لعلاجها.

ما يحمي الصفحة العامة:

- **الرقم يُتحقَّق منه عند الإدخال** — يمني صحيح يصلح لواتساب، وإلا رُفض الطلب بينما
  المريض ما زال أمام الشاشة ويستطيع تصحيحه، لا بعد يومين حين تحاول الاستقبال الاتصال.
- **حدّان يوميّان**: ثلاثة طلبات للرقم الواحد — وهو الحدّ الحقيقي — وستون للمصدر
  الواحد. حدّ المصدر مرفوع عمدًا لأن مشغّلي الجوال في اليمن يشاركون عنوانًا واحدًا بين
  آلاف المشتركين، وحدٌّ ضيّق كان سيمنع مريضة لم ترسل شيئًا. يُطبَّقان على الخادم.
- **بصمة المصدر لا عنوانه**: يُخزَّن تجزئة مملّحة تكفي للعدّ ولا تكشف عنوان مريض.
- **حقل مصيدة** مخفي: البرامج الآلية تملؤه، فيُقبل طلبها ظاهريًا ولا يُكتب.
- **الطلب لا يلمس جدول المواعيد**: أسوأ ما يستطيعه العابث هو ملء قائمة طلبات.

وعند التأكيد يُطبَّق **نفس حارس السعة** الذي يحمي الحجز اليدوي: لا يُحجز في ساعة أكثر
مما يتسع له عدد الكراسي، ويُقترح أقرب وقت متاح بدل رفض مجرّد.

انشر الرابط للمرضى: `https://<نطاق-المركز>/book` — وهو ظاهر في أعلى صفحة الطلبات
لنسخه إلى حالة واتساب.

## المرضى `/patients`

بحث بالاسم أو رقم الجوال أو رقم الملف، وتصفّح مرقّم لكل المرضى، وإنشاء سجل جديد
بالحد الأدنى: **الاسم يكفي**. نموذجٌ من ثمانية حقول أمام مريض واقف ينتهي بسجلات نصف
فارغة أو بلا سجل أصلًا؛ والبقية تُكمَّل من الملف متى توفّرت.

الملف يحمل: الجوال ورقمًا بديلًا، الجنس، سنة الميلاد (والعمر محسوبًا منها)، العنوان،
**تنبيهًا طبيًا**، وملاحظة دائمة — مع تبويبات للمواعيد والزيارات.

- **التنبيه الطبي فوق كل شيء** وبلون لا يُخطئه أحد، ويظهر أيضًا في نتائج البحث:
  حساسية بنج أو مميعات دم تُقرأ **قبل** الإجراء لا بعده.
- **الملاحظة الدائمة** تُكتب مرة وتُقرأ في كل زيارة — «يخاف الإبرة»، «يفضّل آخر
  الدوام». هي الفرق بين عيادة تعرف مريضها وعيادة تبدأ من الصفر كل زيارة.
- التعديل الجزئي يفرّق بين «لم يُرسَل» و«أُرسل فارغًا عمدًا»، فمسحُ رقم بديل خاطئ
  ممكن — قبلها كان يبقى إلى الأبد.
- أسماء المرضى في اللوحة والمواعيد وأعمال المختبر والمتابعة روابط إلى ملفاتهم.

الرقم هو أساس منع تكرار السجلات، فيُخزَّن بصيغة موحّدة (`967…`) أيًّا كان الباب الذي
دخل منه — طلب حجز، أو مريض مشي، أو حجز جلسة قادمة — والبحث يقبل الصيغتين حتى لا
تُعتبر السجلات القديمة مرضى جددًا.

## المالية — ثلاث عملات وصندوق يومي

الأساس **ريال يمني**، والتحصيل بالريال اليمني أو السعودي أو الدولار.

**ثلاث قواعد تحكم كل رقم في هذه الوحدة:**

1. **المبالغ أعداد صحيحة** بالوحدة الصغرى، لا كسور عشرية. `0.1 + 0.2` في جافاسكربت
   ليست `0.3`، وجمع مئة دفعة بحساب عشري يعطي رصيدًا يخالف الورقة بريالات لا يُعرف
   مصدرها.
2. **كل دفعة تحمل سعر صرفها لحظة الدفع.** السعر في اليمن يتغيّر أسبوعيًا؛ لو حُسبت
   الدفعات القديمة بسعر اليوم لتغيّر رصيد كل مريض كلما حُدِّث السعر. السعر يُنسخ في
   صفّ الدفعة ولا يُقرأ من الإعدادات بعدها أبدًا — وكشف الحساب المطبوع أمس يبقى
   مطابقًا لكشف اليوم.
3. **المكافئ يُحسب على الخادم** من المبلغ والسعر: قبولُه من الواجهة يعني دفعةً
   بدولار واحد تُسجَّل بمليون ريال.

**قائمة الأسعار** `/finance/services` — خدمة واسمها وسعرها وتصنيفها. السعر اقتراحٌ
لا قيد: يُعدَّل في كل فاتورة. والخدمة **تُوقَف ولا تُحذف**، لأن حذفها يكسر فواتير
قديمة تشير إليها.

**الفواتير** — بنودها من القائمة أو يدويًا، بخصم اختياري. **الإجمالي يُحسب على
الخادم من البنود** مهما أرسلت الواجهة.

**الصندوق** `/finance` — وردية واحدة مفتوحة لا أكثر، **ولا تُقبل دفعة بلا وردية
مفتوحة**: دفعةٌ خارج الورديات مالٌ دخل ولا يظهر في أي إغلاق. والإغلاق يُقارن الجرد
بالمتوقَّع **لكل عملة على حدة** — من يعدّ الصندوق يعدّ دولارات وريالات كلًّا على
حدة، فمقارنة المكافئ وحده تجعل كل إغلاق يبدو ناقصًا بلا سبب. والفرق يظهر **قبل**
الحفظ: من يرى النقص وهو عند الصندوق يعيد العدّ.

**الاسترداد يُسجَّل دفعةً سالبة الأثر ولا يُحذف شيء** — المحذوف لا يُراجَع.

## المصروفات والمستحقات والعمولات

**سند صرف** لكل مبلغ يخرج، بتصنيف وجهة — ولا يُقبل بلا مستفيد. يمرّ بنفس حراسة
القبض: وردية مفتوحة، وسعر صرف منسوخ في الصف، ومكافئ يُحسب على الخادم. والمتوقَّع في
الصندوق **يطرح المصروف**؛ إهماله أشيع خطأ في إغلاق الصناديق.

**الجهات** `/finance/parties` — مختبرات وموردون وأطباء في جدول واحد، لأن السؤال عنها
واحد: كم لها عندنا وكم دفعنا لها. ولكل جهة كشف حساب: التزاماتها والمدفوع لها والفرق.

**المستحقات** — تكلفة أمر المختبر تُسجَّل التزامًا على العيادة **في نفس معاملة إنشاء
الأمر**: أمرٌ سُجّل وتكلفته ضاعت يعني عملًا بلا أثر مالي، ثم يأتي المختبر بحسابه آخر
الشهر فلا يُقابَل بشيء يُراجَع. وفواتير الموردين تُسجَّل يدويًا. هذا هو الوجه الآخر
لمديونية المرضى: **أن تعرف كم عليك كما تعرف كم لك** — عيادة تعرف مديونية مرضاها ولا
تعرف ما عليها للمختبرات تحسب نفسها رابحة وهي مدينة.

**عمولات الأطباء** `/finance/commissions` — نسبة كل طبيب من عمله، وتُحسب على
**المحصّل لا المفوتر**: عمولةٌ على فاتورة لم تُحصَّل تعني أن تدفع عن مريض لم يدفع ثم
تطارده وحدك. دفعات المريض تُوزَّع على فواتيره بالأقدم أولًا، والتغطية نسبية لا
كل-أو-لا-شيء.

## بنود المصروفات والموازنات التقديرية `/finance/expense-categories`

**البند التشغيلي وحدةُ رقابة.** الكهرباء والإيجار والصيانة والتسويق — كل بندٍ له
حسابه في دليل الحسابات (فالكهرباء 5502 والصيانة الإنشائية 5504 والتسويق 5902)،
وميزانيته الشهرية والسنوية بالريال، وعملة ميزانيته. يُبذر الدليل بالثلاثة عشر
بندًا القياسية أول تشغيل، والمالك يعدّل الميزانيات ويضيف بنوده الخاصة — البند
المخصص صفٌّ مستقل لا يمسّ القياسية.

**الموازنة بلا مقارنةٍ بالفعيّ رقمٌ على ورقة.** لكل شهرٍ يُعرض الفعلي بجانب
التقديري: الاستهلاك، والانحراف بالنسبة، والوفر أو التجاوز — والبنود المتجاوزة
تُبرز وتُفلتر بضغطة. و«مدير البنود» يعمل من المالية أو من الإعدادات
(`/settings/finance-expenses`) بوجهين لمصدرٍ واحد.

**التقرير قابلٌ للطباعة والتدقيق.** تقرير موازنة A4 لكل شهر بفلاتر المجموعة
والحالة، برمز تحقق QR ومرجع تدقيق `AUD-EXP-YYYYMM`، وتصدير Excel عربي RTL
بنفس الأرقام.

## وحدات المال في النماذج — قاعدة ذهبية واحدة

**الدولار والسعودي يُخزَّنان بالسنت والهللة، والريال اليمني بوحدته.** المبلغ الذي
يُكتب في خانة إدخال هو دائمًا **بالوحدات الكبرى** («20» تعني عشرين دولارًا)، والمبلغ
المخزَّن في قاعدة البيانات هو دائمًا **بالوحدات الصغرى** (٢٠٠٠ سنت). التحويل بينهما
يجري بدالةٍ واحدة `parseAmount` عند القراءة ودالتها العكسية `toInputAmount` عند ملء
الخانة — لا قسمة ولا ضرب يدويًّا بـ١٠٠ في أي ملف واجهة، لأن عملة القاعدة يمنية
(وحدتها الصغرى = ١) وكل ضربٍ ثابت بـ١٠٠ كان يضخّم الميزانيات والأقساط والعمولات
مئة ضعف.

**الدرس الذي دفع ثمنه المالك:** تسعيرة الخدمة عشرون دولارًا، فكان «جلب السعر» في
إرسالية المختبر يملأ الخانة بـ٢٠٠٠ (قيمة السنتات المخزَّنة)، ثم يعيد الخادم تحويلها
إلى ٢٠٠٠٠٠ سنتٍ = ألفي دولار عند الحفظ. أصلح ذلك في مواضعه كلها: جلب سعر الإرسالية،
محرر قواعد التسعير (فتح نسخة سعر جديدة / تعديل قاعدة)، ملء الجرد المتوقع عند إقفال
الوردية (للدرج السعودي والدولار)، خانات الموازنات التقديرية ومدخلاتها ونوافذ
الإنشاء والتعديل، تصدير Excel وQR لتقرير الموازنة، والمبلغ المقطوع لعمولة الطبيب،
واقتراح قسط الخطة. ودورة الذهاب والإياب محروسة باختبار: `toInputAmount` ثم
`parseAmount` تعيد المقدار المخزَّن نفسه.

**وتذكيرات مرافقة أُصلحت في المراجعة نفسها:** التكلفة من ملف المريض تطلب الآن مختبرًا
مسجّلًا (فالخادم يرفض تكلفةً بلا جهة)، ورابط «عرض في سجل المعامل» كان يشير إلى مسار
غير موجود، ومعاينة المعادل بالعملة الأساسية في نافذة الترحيل تعيد حساب سعر الصرف
للعملة المختارة لا للعملة القديمة، وإفراغ خانة التكلفة يمحوها فعلًا، ورسائل واتساب
موعد التسليم تمرّ عبر التطبيع القياسي للأرقام.

## الترحيل المحاسبي لأوامر المختبر — «مُرحّل» أم «مسوّدة»

**كل أمر معملٍ قيدٌ ينتظر الاعتراف.** عند إرسال الطلب للمختبر يُختار بند المصروف
وحساباه (مصروف/ذمم)، وحالة الترحيل: **مُرحّل نهائيًّا** فيدخل قيده الدفاتر
المشتقة، أو **مسوّدة** بانتظار المراجعة — بلا تقييد. والفلتر «بانتظار الترحيل
المحاسبي» في شاشة المختبر قائمة عمل المسؤول المالي.

**نافذة الربط المحاسبي** على كل أمر: معاينة القيد قبل الحفظ (مدين مصروف / دائن
ذمم) بحسابيه الفعليين، وترحيلٌ أو إلغاء ترحيل بضغطة، وكل تغيير يكتب أثره في سجل
تتبع الطلب. وحساب المصروف يُحلّ بسلسلة أولوية واحدة: حساب الطلب، ثم حساب بند
المصروف، ثم حساب جهة المختبر (الربط المالي V2)، ثم الافتراضي القياسي.

**وتقرير تدقيق مختبرات** من `/finance/lab-accounting`: لكل مختبر موقعه — حالة
الترحيل التلقائي، المستحق والمدفوع والفارق، وأعماله الجارية — بتصدير Excel وCSV.

## تتبع تذكيرات الأقساط — «آخر تذكير»

**بلا طابعٍ زمني يُزعج المريض كل صباح.** حين يُرسل الاستقبال تذكير واتساب لقسطٍ
مستحق يُوثَّق اللحظة على الخطة وعلى الأقساط المستحقة معًا، فلا يُعاد الإرسال يومين
متتاليين. شاشة `/finance/plans` تعرض عمود «آخر تذكير» بحداثته، وزر واتساب لكل
خطة، و**إرسال جماعي** لكل الخطط المتأخرة دفعةً واحدة — رسالة لكل مريض بنبضته
(الاسم، القسط، الموعد) ثم طابعٌ واحد يشهد.

## التنقل المالي الموحّد — أربع ركائز

**شاشة مالية واحدة تقول من أين تدخل.** الركائز الأربع وفق معايير ADA وRCM:
**النقدية والورديات**، **إيرادات المرضى وأعمار ديونهم**، **التكاليف والمختبرات
والمصروفات**، **الدفاتر والرقابة والتقارير** — شريط ركائز أعلى الشاشة المالية
وتحت كل شاشة مالية روابط مجموعتها، فلا تضيع شاشةٌ لأن أحدًا لم يجدها.

## خطط العلاج `/finance/plans` وتبويب «خطة العلاج» في ملف المريض

طريقان لكائنٍ واحد — لا نوعان من الخطط، لأن المريض قد يبدأ بهذا وينتهي بذاك:

**١) خطة سريرية ببنودها.** لمن عنده أربع حشوات وعصبٌ وتاج: يريد أن يعرف ماذا سيُعمل
له، على أيّ سن، وبكم — قبل أن يوافق. تُنشأ فارغة، وتُضاف بنودها من **دليل الخدمات**
(السعر من الدليل لا من المتصفّح، والاسم والسعر يُنسخان لحظة الاتفاق: الدليل يتغيّر
غدًا والاتفاق لا)، **والإجمالي يُشتقّ من البنود** — رقمان لعملٍ واحد هما بذرة كل
خلافٍ لاحق.

- **الموافقة تُقفل الاتفاق.** بعدها لا يُضاف بندٌ ولا يُحذف: الوثيقة تبقى كما وقّع
  عليها المريض، والمستجدّ يُوثَّق بخطةٍ جديدة. وتُسجَّل الموافقة بوقتها وبيد من
  سجّلها وكيف وُثّقت.
- **وتنقل البنود إلى المخطط السني حالاتٍ مخطَّطة** — لا منجَزة. فيراها كل من يفتح
  الملف، بمن فيهم طبيبٌ آخر يستلم الحالة غدًا.
- **الزيارة الموقَّعة تشطب بنودها** التي نفّذتها وتربطها بها. وبلا هذا يبقى على أحدٍ
  أن يتذكّر تحديث الخطة يدويًّا — فلا يتذكّر، فتُظهر الخطة بعد سنةٍ عملًا أُنجز كأنه
  لم يبدأ.
- **تُفوتَر بزياراتها**، فأرقامها **علاجية**: المتفق عليه، وما أُنجز، وباقي العلاج.
  والمال في تبويب «الحساب» — ولا زرّ «تحصيل قسط» عليها، لأنه يُصدر فاتورةً ثانيةً
  للعمل نفسه.

**٢) خطة بمبلغ متفق عليه تُقسَّط.** وهي ما يكفي مريض التقويم، وتفصيلها أدناه. وإن
شئت الجمع: تُبنى الخطة سريريًّا، ثم تُجدوَل أقساطها **مع الموافقة** — لا قبلها، لأن
الإجمالي لا يستقرّ إلا بها.

وحين تُوقَّع زيارةٌ بإجراءاتٍ من بنود خطةٍ **لها أقساط**، يُحذَّر قبل التوقيع من
فوترةٍ مزدوجة: لا يُمنع بالقوة — قد يكون الإجراء خارج الاتفاق فعلًا — لكنه لا يمرّ
صامتًا.

### الأقساط

ليست ميزة إضافية — هي **نموذج عمل عيادة التقويم**. مريض التقويم يتفق على سعر كامل
ويدفعه على ثمانية عشر شهرًا مع زيارات الشدّ. وبلا خطة يصير حسابه فوضى: فاتورة واحدة
ضخمة تجعله «مدينًا بمليون» من أول يوم، أو فواتير متفرقة لا تقول كم بقي ولا متى ينتهي.

القاعدة التي تحكم التصميم: **الخطة اتفاق، والقسط استحقاق، والدفعة تحصيل** — ثلاثة
أشياء خلطُها هو ما يجعل ملفات التقويم أصعب ملفات العيادة.

- **الإيراد يُثبَّت مع القسط لا مع الاتفاق.** عند تحصيل كل قسط تُنشأ فاتورته ودفعته
  في معاملة واحدة، فيُعترف بالإيراد بقدر ما أُنجز من العلاج. إثباتُ المليون كاملًا
  يوم التوقيع يُظهر ربحًا لم يتحقق ويضخّم مديونية المريض بما لم يستحقّ بعد.
- **الكسر يُحمَّل على القسط الأول.** القسمة تترك كسرًا، وتقريب كل قسط على حدة يجعل
  المجموع يخالف الاتفاق بريالات يجادل عليها المريض بحق. والأول يُدفع اليوم والمريض
  حاضر، بخلاف الأخير بعد سنة وقد نُسي الاتفاق.
- **المتأخر من المستحق حتى اليوم لا من الإجمالي.** من اتفق على مليون ودفع مئتين في
  شهره الثاني ملتزمٌ تمامًا لا متأخرٌ بثمانمئة. والخلط يجعل كل مرضى التقويم يظهرون
  مدينين فتفقد قائمة المتأخرين معناها.
- **التحصيل يُنسب بالأقدم أولًا** كما يوزَّع على الفواتير، لأن المريض يدفع «على
  حسابه» لا على قسط بعينه. ورقم القسط يُشتقّ في الخادم من المدفوع فعلًا لا يُرسله
  المتصفّح.
- التحصيل يمرّ بحراسة القبض نفسها: **وردية مفتوحة**، وسعر صرف منسوخ في الصف — فالقسط
  يُقبض بالسعودي أو الدولار كأي دفعة أخرى.
- الشاشة تُصفّي **متأخر / يستحق قريبًا / الكل**، ولكل خطة زر واتساب برسالة تذكير
  بلهجة تذكير لا مطالبة. وتبويب «خطة العلاج» في ملف المريض يعرض تقدّمه: كم دفع، كم
  بقي، وما تاريخ القسط القادم.

## التقويم — تبويب في ملف المريض

الوحدة التي وُجد البرنامج من أجلها: صاحب المركز أخصائي تقويم، وأكثر مرضاه مرضى
تقويم. وحالة التقويم تختلف عن أي علاج آخر بثلاثة أمور حكمت التصميم: **تمتدّ سنتين
لا زيارةً واحدة**، و**تتقدّم بالأسلاك**، و**تُدفع بالأقساط** مع زيارات الشدّ.

والسؤال الذي تجيب عنه الشاشة في ثلاث ثوانٍ على الكرسي: **على أيّ سلكٍ هو، وماذا
عُمل له آخر مرة، ومتى أراه؟** ولذلك السلكان أولًا وبأكبر خطّ، ثم المرحلة والمدة،
ثم سجلّ الشدّات.

- **حالةٌ مفتوحة واحدة لكل مريض** — والقاعدة تمنع الثانية لا الشاشة: سجلَّا أسلاكٍ
  لفمٍ واحد يعنيان أن الطبيب لا يعرف أيّهما الحقيقي.
- **تسلسل الأسلاك اقتراحٌ لا فرض.** يُعرض التالي في التسلسل المعتاد لشقّ 0.018 أو
  0.022 فيوفّر النقرات في الحالة الغالبة، ويُقبل أيّ سلكٍ يختاره الطبيب بلا اعتراض
  — حالةٌ بعينها قد تستدعي البقاء على السلك نفسه شهرين أو الرجوع خطوة.
- **سلكٌ لم يُذكر في الشدّة يبقى كما هو.** الطبيب يترك الحقل فارغًا حين لا يبدّل
  السلك، وتفسيرُ الفراغ «أُزيل السلك» يمحو الحقيقة بصمت.
- **والشدّة تحدّث سلك الحالة في المعاملة نفسها**، فلا تقول الشاشة سلكًا ويقول السجل
  آخر.
- **لا إكمال بلا مثبّت.** حالةٌ تُغلق بلا مثبّت هي أكثر ما يُفسد نتيجة سنتين: الأسنان
  ترتدّ فيعود المريض بعد عام يجد النتيجة ضاعت — فيلوم المركز بحق. و«لم يُسلَّم» قرارٌ
  صريح يُقبل، لكن لا يُقبل النسيان. والتوقّف غير الإكمال: مريضٌ سافر تُغلق حالته بلا
  شرط، لأنها لا تدّعي أن العلاج انتهى كما يجب.
- **وشاشة الزيارة تعرض سلكيه وآخر ما عُمل له** قبل زرّ التوقيع — فلا يُفتح تبويبٌ
  آخر ولا يُخمَّن.

## الأشعة والمستندات — تبويب في ملف المريض

أن تُفتح صورة الأشعة **في ملف المريض** لا في مجلّدٍ على جهازٍ في غرفة الأشعة هو
الفرق بين سجلٍّ يُقرأ وسجلٍّ يُبحث عنه. والأشعة القديمة أثمن ما في الملف: المقارنة
بين اليوم وقبل سنة هي التشخيص نفسه في كثيرٍ من الحالات.

- **الملفّ على القرص، والقاعدة تحمل وصفه** — الدستور، المحظور الثامن. وليست قاعدةً
  شكلية: صورةٌ بانورامية تُقاس بالميغابايتات، ومئةُ مريضٍ شهريًّا تعني قاعدةً تنتفخ
  حتى تصير كل نسخةٍ احتياطية عمليةً تستغرق ساعة — فلا تُؤخذ.
- **اسم الملف بصمةُ محتواه.** فلا تصادم بين ملفّين اسمهما `IMG_0001.jpg`، ولا تكرار
  إن رُفعت الأشعة مرّتين، ولا مسارٌ يُخمَّن — حارسٌ ثانٍ خلف حراسة الجلسة لا بديلٌ
  عنها. وكل تنزيل يمرّ بجلسة: لا رابط عام لصورة أشعة.
- **الفقد الصامت مرفوض بصوتٍ عالٍ.** حاويةُ النشر مؤقّتة، فما يُكتب على قرصها يزول
  عند أول إعادة نشر. ولذلك يرفض البرنامج الرفع ما لم يُضبط `DOCUMENTS_DIR` على
  مجلّدٍ دائم، ويقول ذلك في الشاشة **قبل** أن يختار أحدٌ ملفًّا. ورفضٌ يُصلَح في
  دقيقة خيرٌ من فقدٍ يُكتشف بعد شهور حين تُطلب الأشعة ولا تُوجد.
- **الحذف إخفاءٌ موثَّق لا محو.** السجل الطبي شهادة، ومن يمحو بصمت يمكن أن يمحو بعد
  شكوى. فيبقى الصفّ ويبقى الملفّ، ويُسجَّل من أخفاه ومتى ولماذا — والسبب إلزامي.
- **النسخة الكاملة ملفّان لا ملفّ**: قاعدة البيانات، وأرشيف الأشعة (`tar.gz` فيه
  مجلّدٌ لكل مريض برقم ملفّه واسمه). وصفحة النسخ تقول ذلك صراحةً — أسوأ من نقص
  النسخة أن تُظنّ كاملة.

## الأرصدة الافتتاحية `/finance/opening`

عيادة قائمة لا تبدأ من صفر. من كان عليه مئة ألف قبل تشغيل البرنامج لا يصير حسابه
صفرًا لأن البرنامج جديد، وبلا هذا تضيع مديونية سنوات في يوم واحد.

**والقيد أصلٌ افتتاحي لا إيراد**: مدين ذمم المرضى، دائن رأس المال والأرصدة
الافتتاحية. الطريقة السهلة أن تُفتح للمريض «فاتورة سابقة» بقيمة ما عليه — وهي التي
تُفسد كل شيء: يدخل دَينٌ عمره سنتان في إيراد هذا الشهر، فتظهر العيادة رابحة بملايين
لم تكسبها في هذه الفترة، وتُحسب عمولات أطباء عن عمل قديم دُفعت عمولته أصلًا.

- **صفٌّ واحد لكل مريض**، وإعادة الإدخال **تصحيح** لا إضافة: رصيدٌ يُدخل مرتين
  بالخطأ يضاعف دَين المريض بصمت، وهو أشيع خطأ في أيام إدخال البيانات القديمة.
- يدخل رصيد المريض ومديونيته وكشف حسابه المطبوع بندًا مستقلًا عن المفوتر، و**عمر
  الدين يُحسب من تاريخه** لا من أول فاتورة في النظام.
- **لا عمولة عليه**: التحصيل يغطّي الأقدم أولًا، والافتتاحي أقدم من كل فاتورة هنا،
  فما دخل منه على دَين سابق لا يدخل وعاء العمولة — وإلا دُفعت العمولة مرتين عن عمل
  واحد.
- **للمدير وحده**، ويُرفض داخل فترة مقفلة: سطرٌ يزيد مديونية مريض بلا فاتورة ولا قبض
  لا يُترك لكل من يجلس على الاستقبال.
- الإدخال من ملف المريض ← «الحساب» ← «رصيد افتتاحي». وشاشة `/finance/opening`
  للمراجعة وحدها: كم أدخلنا وعلى كم مريضًا — فمجموعٌ يخالف الدفتر الورقي يُكتشف
  اليوم لا بعد ستة أشهر من التقارير.

## الدفاتر المحاسبية `/finance/accounting` — قيد مزدوج

ما يفصل «شاشات مالية» عن **نظام محاسبي**: كل حركة مال مقيَّدة في طرفين، مدين ودائن،
بمبلغ واحد. والفائدة ليست شكلية — هي أن الخطأ **يُكتشف**: ميزان المراجعة لا يتوازن
إن ضاع طرف، بينما جدول مدفوعات بلا قيد مزدوج يبتلع الخطأ بصمت إلى الأبد.

**دليل حسابات مرقّم بالنظام المتعارف عليه عالميًا** — 1 أصول، 2 خصوم، 3 حقوق ملكية،
4 إيرادات، 5 مصروفات — فأي محاسب يفتح البرنامج يعرف مكانه فورًا، وأي تصدير إلى
برنامج محاسبي آخر يُقابَل بلا إعادة تسمية.

**قرار بنيوي: القيود تُشتقّ من المستندات لا تُخزَّن معها.** الطريقة الشائعة أن يُكتب
القيد في جدول عند إنشاء كل مستند، وعيبها مصدران للحقيقة: فاتورة في جدول وقيدها في
آخر، وأي خلل في الكتابة المزدوجة يجعل الدفاتر تخالف المستندات ولا يُعرف أيّهما
الصحيح. هنا القيد **دالة** من المستند — فلا تعارض ممكن ولا قيد يتيم. والأرصدة
الافتتاحية مستندٌ كذلك لها جدولها، فتُشتقّ مثلها. وما لا مستند له أصلًا — التسويات
وقيود إعادة التقييم — يُكتب قيدًا يدويًا ويُدمج معها.

- **ميزان المراجعة** بأعمدة مدين ودائن ورصيد، ومجموعٌ يجب أن يتساوى طرفاه.
- **قائمة الدخل على أساس الاستحقاق**: الإيراد من الفواتير لا من التحصيل، والمصروف من
  الالتزامات لا من السداد. عيادة فوترت مليونًا وحصّلت نصفه ربحت بمقدار ما عملت،
  والباقي دَينٌ في الميزانية لا خسارة.
- **الميزانية العمومية**: الأصول = الخصوم + حقوق الملكية، والفرق يُعرض صراحةً — لأن
  ميزانية لا تتوازن تعني خللًا في القيود، وإخفاؤه يجعل النظام يكذب بثقة.
- **دفتر الأستاذ** لكل حساب برصيد متحرّك، وكل سطر يشير إلى مستنده.
- **قيد يدوي** يُرفض إن لم يتوازن أو إن أُسند إلى حساب تجميعي.
- **الخصم يُقيَّد حسابًا مستقلًا** لا يُخصم من الإيراد: من لا يرى كم خصم لا يعرف أنه
  يهدي ربع دخله.
- **فرق جرد الصندوق يُقيَّد** لا يُترك ملاحظة، فيبقى رصيد الصندوق في الميزانية
  مطابقًا لما في الدرج.

**إقفال الفترات**: `finance.locked_before` في الإعدادات. شهرٌ أُقفل لا يتغيّر رقمه
بعد أن قُرئ وصُدّق — وبلا قفل يستطيع قيدٌ يُكتب اليوم أن يغيّر ربح شهرٍ بُنيت عليه
قرارات. التصحيح بعد القفل يكون بقيد في الفترة المفتوحة لا بتعديل الماضي.

## إعادة تقييم العملات `/finance/fx`

الدولار الذي قُبض بسعر ٥٤٥ يدخل الدفاتر بـ٥٤٥ ويبقى فيها بـ٥٤٥. وهذا صحيح
**للحركة** — سند القبض لا يتغيّر بعد طبعه — وخطأ **للرصيد**: مئة دولار في الدرج
اليوم تساوي ما تساويه اليوم.

وبلا إعادة تقييم تكذب الميزانية في اتجاه واحد دائمًا في بلدٍ عملته تنزل: النقد
الأجنبي مقيّد بأسعار قديمة أقل من سعره، فتظهر العيادة أفقر مما هي، ويختفي ربح
التغيّر — وهو ربح حقيقي.

- **القاعدة المتعارف عليها عالميًا (IAS 21)**: البنود النقدية تُعاد ترجمتها بسعر
  الإقفال، والفرق يدخل **قائمة الدخل** لا حقوق الملكية: من احتفظ بدولارات فربح من
  ارتفاعها ربح من قرارٍ اتخذه لا من رأس مال أضافه.
- **شاشة مراجعة قبل الترحيل لا زر يُضغط**: تعرض الوحدات المحتفظ بها، وقيمتها
  الدفترية، و**السعر الضمني** فيها، وسعر اليوم. والسعر الضمني أهم عمود: سعرٌ يبدو
  غير منطقي يعني خللًا في القيود لا فرق صرف، وترحيلُ الفرق حينها يدفن الخلل في حساب
  الفروقات بدل أن يُصلَح.
- **لا ازدواج**: الفرق يُعاد حسابه على الخادم من الدفاتر نفسها، فترحيلٌ ثانٍ في اليوم
  نفسه يجد الفرق صفرًا ويُرفض.
- **الجرد شيء وإعادة التقييم شيء**: الجرد يعالج الفرق بين الدرج والدفاتر، وإعادة
  التقييم تعالج تغيّر السعر — ولكلٍّ حسابه، لأن خلطهما يجعل الاثنين بلا معنى فلا
  يُعرف أضاع الصندوق مالًا أم تحرّك السعر.
- **للمدير وحده**، ويُرفض داخل فترة مقفلة.

- **الشعار واسم المركز على كل تقرير مطبوع** — قرار المالك بعد أن خرجت تقارير باسمٍ

  الإعدادات، وترويسة موحّدة (`ReportPrintHeader`) تحملها إلى كل تقرير: سندات
  الطباعة، مركز التقارير الاثني عشر، التقرير اليومي، التقرير المالي، تقرير الموازنة
  التقديرية، تدقيق حسابات المختبرات، قواعد التسعير، وروشتة المختبر. والطباعة من
  شاشةٍ داخل البرنامج تخفي القوائم والأزرار — فتخرج الورقة تقريرًا لا لقطة شاشة.
- **ترحيلة تصحيح الهوية**: قواعدٌ زُرعت بالبذر الخاطئ القديم (اسم «مركز عقلان لطب
  وجراحة الفم والأسنان» ولقب طبيبٍ آخر) تُصحَّح مرةً واحدة عند الإقلاع إلى
  الافتراضيات الرسمية — بالتطابق الحرفي فقط، فما كتبه المالك بيده لا يُمَسّ.
  والاختبار `__tests__/clinic-identity.test.ts` يمنع عودة الاسم الخاطئ إلى أي ملف.

## أعمال المختبر `/lab`

ثالث المشاكل التي بُنيت الأداة لها: تراكم التراكيب. مشكلة لا يشتكي منها أحد في
الصالة — تظهر يوم يجلس المريض على الكرسي ليركّب تاجه فيُكتشف أنه لم يصل، وقد قُطع له
وعدٌ بيوم.

- المقياس الوحيد **تاريخ الاستحقاق**: عملٌ بلا تاريخ يُنتظر إلى ما لا نهاية.
- الشاشة تفتح على **المتأخر** والأكثر تأخّرًا أولًا — لا على «الكل» ولا بترتيب
  الإرسال: القائمة التي لا يكون أعلاها أهمّها تُقرأ مرة ثم تُهجَر.
- زر واتساب للمختبر برسالة متابعة تحمل اسم المريض والعمل والتاريخ وأيام التأخير —
  رسالة بلا تفاصيل تُجاب بسؤال آخر فتضيع مكالمة ثانية.
- وحين يصل العمل: زر يُبلغ المريض بأنه جاهز للتركيب.
- «وعد بعد ٣ أيام» يؤجّل الاستحقاق حين يعد المختبر بموعد جديد — بلا هذا يبقى العمل
  «متأخرًا» بلا معنى فيفقد اللون الأحمر قيمته.
- عدد المتأخر يظهر كشارة حمراء على زر «المختبر» في اللوحة.

**لا تكاليف ولا فواتير هنا** — المال في النظام الأساسي، وهذه أداة تشغيل.

## المتابعة والاستدعاء `/recall`

سبب وجودها بكلمات المالك: «بدي تتشوه سمعتنا أنه ما في أي اهتمام ولا تواصل». وهذه
ليست مشكلة برمجية — إنها مكالمة لم تُجرَ. الصفحة لا تفعل أكثر من أن تقول: هؤلاء
بالاسم، وهذا نصّ الرسالة، وهذا زر يفتح واتساب.

قائمتان:

- **لم يحضروا مواعيدهم** — متغيّبو الشهر الأخير الذين لم يُتابَعوا. رسالتهم عن موعد
  بعينه، ولا تلومهم: اللوم يفقدك المريض نهائيًا.
- **انقطعوا عن المتابعة** — من مضى على آخر نشاط له أكثر من ٦ أسابيع (أو ٣ أو ٦ أشهر)
  **ولا موعد قادم له**. شرط «لا موعد قادم» هو ما يجعل القائمة صالحة: الاتصال بمن
  انقطع شهرين وهو حاجز الأسبوع القادم يقول له إن العيادة لا تعرف مواعيدها.

القاعدة الحاكمة: **لا يُتصل بأحد مرتين، ولا يُنسى أحد**. كل متابعة تُسجَّل، ومن
استُدعي يخرج من القائمة ثلاثين يومًا ثم يعود إن بقي منقطعًا — مكالمتان في أسبوع
إلحاحٌ لا اهتمام.

## تقرير اليوم `/report`

أول رقم صادق عن يوم في هذا المركز. اليوم يُقاس اليوم بالانطباع — «كان زحمة» أو «كان
هادئًا» — والانطباع لا يُبنى عليه قرار: لا في عدد الكراسي، ولا في ساعات الدوام، ولا
في الاعتذار لمريض انتظر ساعتين.

الحضور · اكتملت زيارتهم · لم يحضروا · متوسط الانتظار وأطوله · متوسط الوقت على
الكرسي · **حِمل الغد** · التراكيب المتأخرة. الأرقام قليلة عمدًا: تقرير من عشرين رقمًا
لا يُقرأ آخر النهار.

- **الانتظار ينتهي عند النداء** لا عند الجلوس، ومن ما زال ينتظر الآن **يُحسب** —
  استبعاده يجعل المتوسط جميلًا في أسوأ الأيام.
- **حِمل الغد** هو الرقم الوحيد الذي ينظر إلى الأمام: معرفة أن الغد ممتلئ ٩٠٪ الليلة
  تعني إعادة ترتيبه الليلة، ومعرفتها صباحًا تعني يومًا آخر منهارًا.
- زر يُرسل الملخص نصًّا في واتساب — التقرير الذي يبقى في الشاشة لا يصل إلى صاحب
  العيادة.

## المستخدمون والصلاحيات `/settings/users`

بلا هذه الشاشة كان الجميع يدخل بحساب المدير الوحيد، فتصير كل فحوص الصلاحيات بلا
معنى، ويصير «من استلم المبلغ» في كل سند اسمًا واحدًا مهما اختلف من استلمه.

| الدور | يرى |
|---|---|
| **مدير** | كل شيء: التقارير والأسعار والعمولات والإعدادات وإلغاء الفواتير |
| **استقبال** | التشغيل والصندوق والفواتير والدفعات — بلا تقارير دخل ولا عمولات |
| **طبيب** | التشغيل وحده: اللوحة والمرضى والمواعيد والمختبر والمتابعة — بلا مال |

- الحماية في **المسارات** لا في إخفاء الأزرار: الطبيب يتلقّى 403 من كل مسار مالي
  و404 من صفحات طباعة السندات. وإخفاء الشاشات من القائمة تحسينٌ للاستخدام لا حماية.
- **آخر مدير فاعل لا يُوقَف ولا يُنزَّل دوره**: عيادة بلا مدير لا يستطيع أحد فيها
  فتح الإعدادات ولا إعادة تعيين مدير — لأن ذلك نفسه يحتاج مديرًا.
- اسم الدخول بالإنجليزية والأرقام فقط: يُكتب على لوحة مفاتيح قد تكون بالإنجليزية،
  ومسافةٌ في آخره خطأٌ لا يراه أحد ويمنع الدخول إلى الأبد.
- **لا حذف — إيقاف فقط**: سندات المستخدم تبقى باسمه في السجل، وحذفه يجعلها بلا
  مستلم معروف.

## تصدير البيانات `/settings/export`

نسخة احتياطية بصيغة CSV، وملف يُرحَّل به إلى برنامج آخر. عشرة جداول: المرضى،
المواعيد، الزيارات، الفواتير وبنودها، سندات القبض والصرف، الالتزامات، أعمال المختبر،
ودفتر اليومية بكل قيوده.

- **علامة ترتيب البايتات (BOM)** في أول كل ملف: بلا ثلاثة بايتات تفتح Excel الملف
  العربي حروفًا مشوّهة، فيظنّ صاحب العيادة أن البيانات تلفت.
- رؤوس الأعمدة **بالعربية**: ملفٌ برأس `base_amount_minor` لا يقرأه صاحب العيادة ولا
  محاسبه.
- الفاصلة والسطر الجديد وعلامة الاقتباس داخل النصوص محميّة: أيّها يُفسد الملف صامتًا.
- التصدير **للمدير وحده** — يُخرج كل بيانات المرضى والمال في ملف واحد.

**ملفٌ على نفس الحاسب ليس نسخة احتياطية.** أرسله إلى بريدك أو إلى السحابة بعد كل
تنزيل، ونزّله شهريًا على الأقل.

## تسجيل الدخول

كل شيء خلف الباب: أي مسار وأي طلب API بلا جلسة صالحة يُرفض. الحماية في `middleware.ts`
بقائمة **مسموح** لا قائمة ممنوع — فمسار جديد يُضاف غدًا يكون محميًا تلقائيًا، ونسيانه
يعني إغلاقه لا كشفه. ولأن `middleware` يعمل على Edge بلا `node:crypto`، يفحص وجود
الكوكي فقط، ويجري التحقق من التوقيع داخل كل مسار يلمس بيانات مرضى.

كلمات المرور مُجزّأة بـ scrypt بملح لكل مستخدم، والمقارنة ثابتة الزمن. الجلسة كوكي
موقّعة `HttpOnly` و`Secure` و`SameSite=Lax` تنتهي بعد 12 ساعة.

### أول تشغيل

1. أضف `SESSION_SECRET` و`SETUP_TOKEN` في متغيرات النشر.
2. افتح `/setup`، وأنشئ حساب المدير.
3. **احذف `SETUP_TOKEN`** من إعدادات النشر — انتهى عمله.

الصفحة تُغلق نفسها بعد أول حساب، لكن حذف الرمز يقفل الباب من طبقتين لا واحدة.
