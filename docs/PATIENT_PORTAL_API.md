# عقد واجهة برمجة بوابة المريض (`Patient Portal API Contract`)

يوفّر هذا المستند العقد البرمجي النظيف والموثّق لواجهة **بوابة المريض** في نظام **مركز الدكتور عقلان الكامل لتقويم وزراعة وتجميل الأسنان**، بحيث تخدم واجهة الويب الحالية (`/portal`) وتكون جاهزة للربط المستقبلي مع **تطبيق المرضى الخاص على الهواتف الذكية** عند استكماله واعتماد قرار الإطلاق من مالك المركز.

> **تنبيه معماري صريح:** تطبيق المرضى المستقل للهواتف الذكية (iOS / Android) مرحلة لاحقة مستقلة لم يُبنَ بعد؛ هذا المستند يوثّق طبقة الـ API الخلفية الجاهزة والآمنة التي سيعتمد عليها التطبيق دون ازدواجية منطق أو حسابات مالية.

---

## 1. مبادئ الأمان والمصادقة المشتركة

1. **رفض قاطع للدخول برقم الهاتف وحده:** المسار القديم المبني على الهاتف وحده متقاعد نهائيًا ويردّ بـ `403`؛ كل حساب مرتبط بـ `patient_id` صريح واسم مستخدم فريد (`loginName`) وكلمة مرور مملّحة بـ `scrypt`.
2. **الجلسة الموقّعة والتحقق الحي من قاعدة البيانات:**
   - كوكي الجلسة: `aqlan_portal` (`HttpOnly`, `Secure`, `SameSite=Lax`).
   - يتحقق الخادم في كل طلب عبر `requirePortalSession()` من:
     - صلاحية التوقيع وعدم انتهاء `expiresAt`.
     - بقاء الحساب `status = 'active'`.
     - مطابقة `credentialVersion` وعدم صدور الجلسة قبل `sessions_revoked_at`.
     - مطابقة بصمة رقم الهاتف (`phoneFingerprint`) لمنع بقاء جلسة صالحة بعد تغيير رقم التواصل.
3. **العرض الإداري للقراءة فقط (`Admin Read-Only Preview`):**
   - يعمل عبر الكوكي المستقل `aqlan_portal_preview` بهوية الموظف الإداري نفسه وسببه المسجّل.
   - تُرفض جميع طلبات الكتابة أو التعديل (`POST` / `PATCH` / `DELETE`) أثناء العرض الإداري برمز `403` — باستثناء `/api/portal/admin-preview/exit`.
4. **حماية CSRF وحدود الطلبات والقفل المؤقت:**
   - جميع طلبات التعديل محمية بفحص `Origin` / `Host` الصارم في `proxy.ts`.
   - تخضع مسارات الدخول والتفعيل والاستعادة وتغيير كلمة المرور لـ `consumeSecurityLimit` بالإضافة إلى القفل المؤقت على مستوى الحساب (`423 Locked` — `account_locked`) بعد استنفاد `maxFailedLoginAttempts`، وحرق الرابط المؤقت (`410 Gone`) بعد `maxTokenAttempts`.
5. **أوضاع التشغيل الثلاثة (`operatingMode` في `patient_portal_settings`):**
   - `disabled` (الافتراضي الآمن — Fail-Closed): التفعيل وإصدار الروابط موقوفان.
   - `sandbox_test`: البوابة عاملة بالكامل للفحص ببيانات اصطناعية، مع **منع تلقائي لأي إرسال خارجي عبر واتساب أو SMS** وإرجاع `sandboxSimulated: true` للمعاينة المحلية.
   - `live_enabled`: محصور بمالك المركز المعتمد حصريًا، ومقفَل برمجيًا في بيئة الإنتاج (`isProductionLiveLaunchLocked()`) حتى يقرر المالك الإطلاق الرسمي.

## 2. مسارات المريض العامة والمصادقة (`/api/portal/*`)

| المسار | الطريقة | الوصف والاستجابة |
|---|---|---|
| `/api/portal/bootstrap` | `GET` | بيانات التمهيد العامة الآمنة قبل الدخول: هوية المركز، وضع التشغيل الفعّال، إتاحة رابط الحجز، وإعلانات المركز النشطة ضمن نافذتها الزمنية (`startsAt`..`endsAt`). لا يعيد أي بيانات مرضى إطلاقًا. |
| `/api/portal/login` | `POST` | تسجيل الدخول بـ `{ username, password }` (يرفض `{ phone }` بـ `403`). يعيد `200` مع كوكي الجلسة، أو `401` (`invalid_credentials`)، أو `423` (`account_locked` + `Retry-After`)، أو `429`. |
| `/api/portal/activate` | `GET` / `POST` | `GET ?token=...` يفحص صلاحية رابط التفعيل المؤقت أحادي الاستخدام؛ `POST { token, password }` يعيّن كلمة المرور لأول مرة ويبطل الرابط فورًا ويصدر جلسة جديدة. |
| `/api/portal/reset-password` | `GET` / `POST` | `GET ?token=...` يفحص رابط الاستعادة؛ `POST { token, password }` يحدّث كلمة المرور ويرفع `credential_version` لإبطال جميع الجلسات السابقة فورًا. |
| `/api/portal/logout` | `POST` | يمسح كوكي جلسة المريض وكوكي المعاينة الإدارية. |
| `/api/portal/me` | `GET` | يعيد حالة الجلسة الحالية، ووضع التشغيل، ومفاتيح الأقسام المسموح بعرضها (`visibleSections`)، وملخص الملف الشخصي الآمن (`profile` بهاتف مقنّع وبدون تنبيهات داخلية)، ومعلومات `adminPreview` إن وجدت. |
| `/api/portal/change-password` | `POST` | تغيير كلمة المرور ذاتيًا `{ currentPassword, newPassword }` من داخل جلسة المريض النشطة، مع إبطال جلسات الأجهزة الأخرى وإصدار كوكي محدّث للجهاز الحالي (محظور `403` في العرض الإداري). |
| `/api/portal/sessions/revoke` | `POST` | إنهاء جميع الجلسات النشطة على كافة الأجهزة فورًا برفع `credential_version` وتسجيل `portal.account.sessions_revoked` (محظور `403` في العرض الإداري). |

## 3. مسارات البيانات السريرية والمالية والتواصل للمريض (`/api/portal/*`)

تحترم جميع المسارات التالية مفاتيح الإظهار المضبوطة في `patient_portal_settings` وتعيد `403` برسالة عربية واضحة إذا أوقفت الإدارة القسم المعني:

| المسار | الطريقة | المصدر والضمانات الأمنية |
|---|---|---|
| `/api/portal/appointments` | `GET` | المواعيد القادمة + سجل المواعيد السابقة (`pastAppointments`) + علمي `allowConfirm` و`showBookingLink`. معرّف المريض يؤخذ من الجلسة حصرًا. |
| `/api/portal/appointments/confirm` | `POST` | تأكيد حضور الموعد `{ id }` إذا كان `allowAppointmentConfirm = true` والجلسة ليست عرضًا إداريًا. |
| `/api/portal/clinical` | `GET` | الزيارات السريرية الموقّعة فقط (`signed_at IS NOT NULL` — تُستبعد المسودات غير المعتمدة كليًا) + خطط العلاج النشطة/المكتملة مع نسب الإنجاز (تُربط المبالغ المالية بمفتاح `showStatement`). |
| `/api/portal/prescriptions` | `GET` | الروشتات الطبية الصادرة الفعّالة فقط (`status = 'active' AND voided_at IS NULL`) مع بنود الأدوية والجرعات وتعليمات الطبيب. |
| `/api/portal/statement` | `GET` | كشف الحساب المالي المطابق لكشف الحساب المطبوع من دفتر الأستاذ المعتمد (`patientLedger`): الأرصدة لكل عملة، الرصيد الافتتاحي، العلاج السابق، الفواتير وبنودها، اتفاقات العلاج، والدفعات. |
| `/api/portal/documents` | `GET` | قائمة المستندات والتقارير المملوكة للمريض غير المحذوفة؛ تخضع صور الأشعة والصور السريرية لمفتاح مستقل `showXrayDocuments` (افتراضيًا `false`). |
| `/api/portal/documents/download` | `GET` | تنزيل آمن لمستند `GET ?id=<docId>` بعد فحص ملكية الصف ونوع المستند المسموح به، مع ترويسات `Content-Disposition: attachment` و`X-Content-Type-Options: nosniff`؛ يعيد `404` موحّدة لمستندات المرضى الآخرين لمنع استكشاف المعرّفات. |
| `/api/portal/intake` | `GET` / `POST` | قراءة وإرسال نسخة إلحاقية جديدة من الاستمارة الصحية الأولية للمريض. |
| `/api/portal/messages` | `GET` / `POST` / `PATCH` / `DELETE` | محادثة المريض مع العيادة مع احترام `allowMessageAttachments` و`allowVoiceMessages`؛ الحذف يخفي الرسالة من الواجهة وتنزيل المرفقات مع الاحتفاظ الآمن بالسجل في العهدة دون إتلاف نهائي تلقائي. |

## 4. مسارات الإدارة والطاقم المخوّل

| المسار | الطريقة | الصلاحية والوظيفة |
|---|---|---|
| `/api/patients/[id]/portal-account` | `GET` / `POST` | عرض حالة حساب المريض وإصدار روابط التفعيل (`activate`) والاستعادة (`send_reset` / `in_person_reset`) وإبطال الجلسات والتعطيل وفك القفل المؤقت (`unlock`)، وفق صلاحيات `canIssueActivation` و`canIssueReset` و`canChangeRecoveryPhone` و`canManagePortal` ونطاق الوصول للمريض، مع فرض توثيق الهوية عند الهاتف العائلي المشترك. |
| `/api/patients/[id]/portal-preview` | `POST` | بدء جلسة «عرض بوابة المريض» الإدارية للقراءة فقط للمالك أو المدير المخوّل بـ `canPreviewPortal` مع إلزام سبب مكتوب وتسجيل `portal.admin_preview.start`. |
| `/api/portal/admin-preview/exit` | `POST` | إنهاء العرض الإداري وتسجيل `portal.admin_preview.exit` بمدته الزمنية. |
| `/api/settings/patient-portal` | `GET` / `PATCH` / `POST` | قراءة وضبط إعدادات وسياسات البوابة (`PATCH` محصور بالمالك أو المدير المفوّض بـ `canConfigurePortalSettings`؛ وتفعيل `live_enabled` محصور بالمالك وحده)، وتحديث مصفوفة صلاحيات الموظفين (`POST`). |
| `/api/settings/patient-portal/announcements` | `GET` / `POST` / `PATCH` / `DELETE` | إدارة إعلانات وأخبار المركز على شاشة البوابة (إضافة، تعديل، إعادة ترتيب، تفعيل/إيقاف، جدولة `startsAt`/`endsAt`، ووسم النماذج التجريبية `isSample`) مع تسجيل كل تعديل في `audit_log`. |
| `/api/settings/patient-portal/retained-messages` | `POST` | معاينة إدارية مدقّقة لسجل رسالة محذوفة محفوظة في العهدة الآمنة للإدارة ذات النطاق الكامل مع سبب مراجعة إلزامي (`>= 8` أحرف) وتسجيل `message.retained.inspect`. |
