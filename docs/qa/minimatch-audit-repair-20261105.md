# Minimal minimatch audit repair

## Scope

Based on main `6a6bdc0cc705874fd4ff6d0f0ddc3fdcd314e9e6`. This change repairs the
existing dependency-audit failure also observed in PR #526; it does not include
that PR's supplier-print changes or the separate PR #506 application changes.

The official [GHSA-g3hv-75wg-m249 advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249)
reports an affected range of `>=7.0.0 <11.0.1`. Baseline npm audit identifies only
`@typescript-eslint/typescript-estree`'s nested `minimatch@10.2.6` copy, with seven
moderate entries after transitive attribution. The existing `minimatch@3.1.5`
consumers are outside this advisory's affected range.

The sole new override is version-scoped:
`@typescript-eslint/typescript-estree@8.70.0` → `minimatch@11.0.3`.
The lockfile was regenerated by npm from official registry metadata. It changes
only the nested minimatch package and adds its official
`@isaacs/nonrecursive-glob-match@1.0.3` dependency. Both are development-only.

Official package metadata:
- https://registry.npmjs.org/minimatch/11.0.3
- https://registry.npmjs.org/@typescript-eslint%2ftypescript-estree/8.70.0

The fixed archive integrity is
`sha512-iny/40PEGkNJQ5/Pv6z3nm6FbRAby32GeZRjCUJk2WnNDbgPSTcdI+DDvLqsgBdD4cD5sMtMheqPPnehCCa8Nw==`.
Its Node range (`18 || 20 || >=22`) supports the unchanged project Node 22 contract.

## Compatibility and enforcement

The override deliberately crosses the consumer's declared `^10.2.2` range.
The actual installed consumer uses the named CommonJS `minimatch` function with
`{ dot: true }` to enforce project-service `allowDefaultProject` patterns. Tests
exercise that API and the real TypeScript-ESLint parser, including a dotfile and
a rejected file outside the allowlist. They also verify legacy ESLint consumers
still receive minimatch 3's callable CommonJS export and existing lint rules work.

The existing strict override guard admits exactly this consumer/version/package
combination. Tests reject global overrides, changed versions, ranges, aliases,
local substitutes, and overrides on incompatible legacy consumers. Existing
parser hardening and braces provenance checks remain intact. No vulnerability
report filtering, audit exception, threshold, workflow, or lint-rule change is made.

Unlike candidate `171ae786`, this fix does not upgrade ESLint 9.39.5 or React Hooks
6.1.1, raise the Node floor, or import application compatibility edits. ESLint 9
is deprecated upstream; that broader migration remains separate work.
