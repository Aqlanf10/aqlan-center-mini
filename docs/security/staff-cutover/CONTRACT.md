## Inventory interpretation and reproducibility

`inventory.json` contains every explicit route HTTP export plus every matrix route/method, every page, and every layout in supported `.js`, `.jsx`, `.ts`, and `.tsx` formats. Entry-like filenames in other formats are preserved as `unknown` source issues and fail the drift checker; they are never silently omitted. Duplicate route filenames and route files without recognized exports are also flagged for review. Matrix values are parsed as TypeScript AST constants, not inferred from URL role guesses. Missing API exports/matrix entries are discrepancies. Two non-API manifest routes are explicitly unknown, not matrix errors. Framework implicit HEAD/OPTIONS and static assets are outside the explicit-export inventory. The existing matrix does not declare every semantic sub-operation within a handler; body-action branches and imported helper call graphs need workflow review before promotion.

Classification is deliberately conservative:

* `staff-legacy-held`: every role-array matrix operation, public staff auth transport, and non-public staff page. Existing marker-free behavior is not condemned; marker-bearing canonical acceptance is unproved.
* `public-separate-portal`: only explicitly recognized public/portal/internal/webhook transport classes or proxy public pages other than staff entry. This is separation of admission, **not evidence of availability with markers**. Root layout, shared database helpers and external effects still require regression.
* `unknown`: shared-media branches (portal separate, staff held), print pages, non-API manifests, an unrecognized matrix access class, an unsupported entry filename, or a matrix/export discrepancy. Unknown is a blocker, never permission.
* `canonical-ready`: none. Adding import names cannot promote an operation. Promotion requires the reviewed operation contract and passing marker-bearing built-application journey, not a counter heuristic.

`workflow` is a deterministic path-family routing aid, not a claim of exhaustive semantic authorization. `other-review-required` must be dispositioned, not silently excluded. Existing AI/Dot surfaces remain recorded for enumeration; future AI/Dot work is excluded. Every other existing required route/branch must be migrated or explicitly dispositioned with the user before cutover; inventory is not a license to drop workflows.

The source digest covers app/components/lib `.js`, `.jsx`, `.cjs`, `.mjs`, `.ts`, `.tsx`, `.cts`, `.mts` sources and proxy; direct helper evidence includes lexical symbol references (including imports, calls and comments), **not a transitive call graph**. Counts are measured file/method counts, not completion percentages. Exact baseline: 411 explicit route-method entries (409 API, 2 non-API), 95 pages; see generated summary for classifications. The 248 legacy-reference files use the listed helper set and app/components scope; this is not interchangeable with an earlier narrower 247-file search.

### Acceptance that would actually establish the first slice (not run here)

Use disposable real PostgreSQL and a built application, existing guards enabled. Install only explicitly approved synthetic fixture schema; create target-local ready owner and a non-owner with narrow grants through the reviewed fixture/protocol. Use real signed HTTP cookie entry, not arbitrary JSON claims. Verify login→auth/me→shell→staff list; owner edits one allowed permission; narrow user sees only authorized UI and server data; fresh permission revision revokes stale session; unauthorized API direct invocation denies; permission change/audit commit together. Add actual concurrent edit/revoke and expiry-after-lock-wait checks, not fake journeys returning canned success.

Negative cases: partial/v1/quarantined schema; stale realm/generation/registry/control/account/permission/provider epochs; numeric-ID reuse and username rename consistency; forged/copied handles; wrong client/action/XID; mixed markers, malformed/expired signature, canonical-cookie+legacy-Bearer downgrade; absent grant, unlinked clinician, self-escalation, owner replacement, credential revocation. Verify writes roll back on final admission failure. No canonical failure may reach legacy auth, and no legacy token may authorize against marker-bearing state. Verify marker-free login/shell/current routes still work in a separate fixture. Existing public/portal/media/print surfaces must not leak data or become accidentally unavailable.

For the eventual clinic release, extend the same real HTTP/DB evidence to each required workflow: read consistency, record scope, write audit/idempotency, concurrency/expiry/revocation, and external-effect handling. Existing `__tests__/postgres/staff-operation-runtime.test.ts`, canonical inventory suites, legacy read-fence suites and `__tests__/security-http/http-permission-matrix.test.ts` are useful lower-level evidence, **not substitutes** for those journeys. No positive canonical full-clinic journey exists in this artifact.
