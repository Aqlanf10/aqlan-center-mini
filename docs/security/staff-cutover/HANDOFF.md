## 1. القيود الملزمة (من المالك ومن Dot)

لا يُخالَف أيٌّ منها.

- لا Production، ولا دمج إلى main/REVIEW، ولا نشر (deploy).
- قول المالك: «لا تنشر التطبيق أبدًا إلا بعد أن تجرّبه أنت وأجرّبه أنا على الـ Staging».
- Staging فقط وعند الاكتمال. الـ PR يبقى Draft.

### 1.2 Git

- لا force-push.
- لا حذف لفروع الآخرين.
- لا تعديل لهجرات منشورة.

### 1.3 الهجرات

### 1.5 الاختبارات والإعدادات

- لا تعطيل أو إضعاف للاختبارات أو الحمايات.

  ```

  ```
- لا تُكتب "@dot" عارية. الردّ للمالك بالعربية.

## 3. المفاهيم التقنية (اقرأها قبل كتابة أي شريحة)

### 3.1 الكتابة

- `withStaffOperation(pool, session, action, work)`:
  - معاملة READ COMMITTED.
  - سياج دورة حياة مشترك.
  - إثبات FOR SHARE لمنح الجلسة.
  - أي رمي داخلها يعني ROLLBACK.
- الأكشن يجب أن يكون في `CLINIC_RUNTIME_ACTIONS`، وهو حاليًا:

  ```
  ["patients.create","patients.edit","settings.view","visits.manage","appointments.edit","appointments.create"]
  ```
- القائمة نفسها محفوظة في مكانين يجب أن يتطابقا:
  - Set حرفي في `lib/staff-operation-runtime.ts`.
  - الـ pin في `scripts/audits/staff-cutover-readiness.test.mjs`.
- مساعدات داخل المعاملة:
  - `staffOperationCapabilities(client, handle, action, [caps])` تعيد Set لما يملكه.
  - `staffOperationPatientScope` و `staffOperationAppointmentScope` تعيدان `{kind:"none"|"all"|"own", clinicianPartyId}`.
  - `staffOperationClinician` و `staffOperationIdentity` (للحصول على username/userId/role).

### 3.2 القراءة

```
runCanonicalReadSnapshot(session, "read:...", (query, scope) => ..., { errorPrefix, maxBytes })
```

- لقطة مالكة واحدة لكل قراءة.
- القراءات مسجّلة في `lib/canonical-record-reads.ts`.

### 3.3 دلالات النطاق

- **المرضى:** `own` تعني `DOCTOR_PATIENT_CONDITION` عبر `patientInDoctorScopeWith`.
- **المواعيد وقائمة الانتظار:** `own` تعني `doctor_id = clinician party`. غير المسند لا يظهر.
- خارج النطاق يُجاب **مطابقًا تمامًا** للمفقود: 404، والرسالة نفسها والكود نفسه. هذا يُختبر في كل شريحة.

### 3.4 مجموعات الإسقاط (projection)

| المجموعة | الشرط | الملاحظة |
|---|---|---|
| care | `PATIENT_CARE_CAPABILITIES` | |
| operational | `patients.operational-summary.view` | وجود التنبيه فقط، لا نصّه |
| balances | `finance.patient-ledger.view` | |

المجموعة المخفية تُحذف مفتاحًا، لا تُرسل فارغة.

### 3.5 نمط الكاتب القابل للحقن

- `xxxWith(client, ...)` يأخذ معاملة المستدعي.
- الغلاف القديم `xxx(...)` يبقى بمعاملته الخاصة **دون تغيير سلوكي**.
- **التدقيق:**
  - المسار القانوني يستعمل `insertAuditRow(client, ...)`، فهو ذرّي ويرمي عند الفشل.
  - المسار القديم يبقى best-effort.
- **محرّك السعة:**
  - `bookAppointment(input, actor, { client, audit })`.
  - `rescheduleAppointment(input, actor, { client, audit })`.
  - `writeAppointmentInDay({client})` و `writeAppointmentAcrossDays({client})`.
  - مع `client` لا BEGIN ولا COMMIT ولا ROLLBACK في الكاتب.
- **الفاعل القانوني** للمحرّك: `role: "canonical"`. بذلك لا ينطبق تجاوز المدير بالدور ولا الإسناد الذاتي للطبيب، والمنح وحدها تقرّر. التجاوز فقط بـ `appointments.override-capacity`.

### 3.6 المسارات (route)

في أول الدالة:

```ts
const selected = await selectRequestStaffEnvelope();
if (selected.kind === "denied") /* 401 */;
if (selected.kind === "canonical") { /* الفرع القانوني */ }
```

- الكوكي القانونية **لا تسقط أبدًا** إلى الجلسة القديمة.
- الأخطاء تُحوَّل عبر `canonicalWaitingFailure` أو `canonicalPatient*Failure` في `lib/canonical-patient-http.ts`.
- الردود تحمل الترويسة `NO_STORE`.
- أي 4xx/5xx يحمل `message` عربيًا.

### 3.7 الصفحات

- الصفحات القانونية مسجّلة في `lib/canonical-navigation.ts`.
- التفرّع:
  - إما early return في الصفحة.
  - أو `layout.tsx` (مثل `app/appointments/layout.tsx`)، لأن اختبارات الوحدة تستدعي `Page()` مباشرة.

### 3.8 بعد أي تغيير في المسارات أو الصفحات

```bash
node scripts/audits/staff-cutover-readiness.mjs --write
node scripts/audits/m2-route-scan.mjs --write
```

- تحديث `docs/security/staff-cutover/M2_ROUTE_CAPABILITY_MAP.json` بتعديل نصّي دقيق للـ `note`/`status`، **لا** بإعادة تسلسل JSON. إعادة التسلسل تغيّر 12 ألف سطر.
- إضافة قسم "Slice N" في `M2_ROUTE_CAPABILITY_MAP.md` قبل عنوان `### Single-snapshot guard`.

### 3.9 فخاخ معروفة

- `lockChairDay` ثم صفّ الزيارة: هذا ترتيب الأقفال القديم.
- المواعيد:
  - أقفال الأيام المرتّبة أولًا، ثم صفّ الموعد.
  - استثناء: الانتقالات (transitions) تقفل صف الموعد أولًا.
- `appointments` تستعمل `scheduled_date`/`scheduled_time`.
- `appointment_services` تحتاج `code`.
