# إعادة طباعة الإقرار الموقّع — أدلة اصطناعية

مرضى ومستندات اصطناعية فقط (مولَّدة داخل الاختبار `consent-reprint-integrity.test.ts`).

## قبل الإصلاح (main `f20ea16`)
- `consent-MAIN-before-facts.json`: وقائع قياس فعلية على الصفحة القديمة.
- `consent-MAIN-before-signed.png`: الإقرار المحفوظ يظهر بنص القالب الحالي وعنوانه لا بما سُجّل.
- `consent-MAIN-before-forged.png/.pdf`: رابط بموقّع وطبيب وتاريخ مزوّرة، والتوقيع المحفوظ ظاهر تحتها. PDF بمقاس Letter.
- `consent-MAIN-before-photo-as-signature.png`: صورة سريرية (kind=photo) تُعرض كأنها توقيع.
- في الـfacts أيضًا: مستند محذوف يظهر، ومستند مريض آخر يسقط إلى القالب بلا وسم، وطبيب بلا `canViewXrays` يرى الصفحة (200) مع أن المستند نفسه 403.

## بعد الإصلاح
- `consent-signed-*`: إعادة طباعة من السجل المحفوظ وحده (A4، صفحة واحدة، RTL).
- `consent-blank-*`: «نموذج غير موقّع» بعلامة مائية، بلا توقيع.
- `consent-refused-*`: رفض واضح بدل نموذج يبدو موقّعًا.
- الأحجام: 1280 و390 وPDF.

## حدود المستندات القديمة
السجلات الحالية لا تحفظ نص الإقرار (الملاحظة JSON بلا `terms`)، فلا يُعاد بناؤه من القالب الحالي. تُعرض البيانات المحفوظة
(القالب، الموقّع، الصفة، العنوان، الإجراء، التاريخ، من سجّل) مع إشعار «لم يحفظ هذا السجل نص الإقرار». إن وُجد
`terms` في السجل عُرض هو.

## تبعية خارج النطاق (لدوت)
`ConsentModal` يجب أن يحفظ لقطة نص (terms/risks/postOpInstructions) عند التوقيع. مسار الرفع الحالي
`/api/patients/[id]/documents` يقصّ الملاحظة عند 300 حرف، فلن تتسع لقطة كاملة هناك؛ تحتاج حقلًا/عمودًا مخصصًا. لم يُلمس.

## مراجعة دوت (5450100011) — ما عولج في هذا الطلب

- **تاريخ التوقيع غير المسجَّل يبقى غير معروف.** كانت الصفحة تكتب `takenOn ?? uploadedAt` تحت «تاريخ التوقيع». الآن:
  `signedOn = takenOn ?? null`، فتظهر «غير مسجّل في السجل»، ووقت التسجيل يُذكر منفصلًا ويُقال إنه ليس تاريخ التوقيع.
  والعمر يُوصف بأنه «العمر الحالي». يثبته اختبار HTTP بإقرارٍ محفوظ بلا `takenOn`، مع ثبات صف المستند وبايتاته.
- **النص المحفوظ الناقص يظهر ناقصًا.** القراءة انتقلت إلى `lib/consent-record.ts`. القسم الغائب أو المشوَّه يُعرض
  «غير محفوظ» أو «غير مقروء»، والبنود الفارغة أو البيضاء لا تُعدّ نصًّا كاملًا. لا يُملأ شيءٌ من قالب اليوم ولا بقائمةٍ فارغة.
  تثبته اختبارات وحدة للقارئ واختبار HTTP بإقرارين: الأول ببنودٍ فقط، والثاني ببنودٍ فارغة.

## عيب التقاطٍ معروف — متتبَّع، وإصلاحه خارج هذا الطلب

شاشة التوقيع (`ConsentModal`) تحفظ سجل الإقرار JSON في ملاحظة المستند، ومسار الرفع يقصّ الملاحظة عند 300 حرف
(`rawNote.slice(0, 300)`). الحمولة الفعلية التي تبنيها الشاشة (`buildConsentNotePayload`، وهي المصدر الواحد الآن) قد
تتجاوز الحد بقالبٍ عادي وموقّعٍ قصير الاسم: خلع جراحي باسم «أحمد علي» = 323 حرفًا، بحسب مراجعة دوت.

النتيجة: يُحفظ JSON مقطوع، فيرفض القارئ الصارم طباعة نسخةٍ موقّعة. **هذا الرفض صحيح ويبقى** (fail closed)،
وتثبته `__tests__/consent-record.test.ts`.

الإصلاح الآمن للالتقاط يحتاج تعديل مسار الرفع أو مكان حفظ البيانات الوصفية، فيُقدَّم في تغييرٍ منفصل. لا يُعاد
كتابة سجلٍّ قديم، ولا يُختلق نصٌّ أو تاريخ.

## أدلة التشغيل نفسه في سجل CI (مراجعة 5461832436)

اختبار `consent-reprint-integrity.test.ts` يكتب ملفات التشغيل نفسه (signed/blank/refused × 1280 و390 وPDF) في سجل CI بصيغة
`SYNTHETIC_PRINT_EVIDENCE_V1` (النطاق `consent-reprint`)، مع SHA-256 وهوية التشغيل والـcommit المسحوب ووالديه، و`acceptance: true`.
يُقبل كل مشهد بعد نجاح كل تأكيداته فقط، ولا تُرسل المجموعة إلا كاملة. `decodeEvidence()` يعيد بناءها ويتحقق منها؛ محليًا طابقت الملفات
التسعة بايتًا ببايت. **هذا لا يصلح عيب الالتقاط (قصّ الملاحظة عند 300 حرف)؛ يبقى مفتوحًا.** بوابات CI وخطوات الرفع بلا تغيير.
