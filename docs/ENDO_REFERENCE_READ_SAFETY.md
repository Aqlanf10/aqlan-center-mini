# ENDO reference read safety

This bounded change withdraws an earlier ENDO read while a new read is pending or failed. Both ENDO and case reads share patient/session access: 401/403/404 from either endpoint withdraw all references at response headers and abort that generation, without awaiting an error body. A later successful peer response cannot regrant access. Plan permission denial instead returns 200 with planVisible:false. Successful clinical documentation can resume when the separate case/plan projection has an ordinary network, 503, JSON or envelope failure; that failure never means no plan exists and cannot authorize new-case creation or crown-plan linking.

Authority-read generations are independent of mutation sequences. Starting or failing a valid clinical save while cases are pending does not cancel their authoritative denial handling. A hard read denial also retires the current mutation sequence; even a late successful save response cannot republish the retired clinical context. A mutation's own access denial aborts its pending reference reads.

The existing editor, record fields and mutation APIs are preserved. A same-owner draft remains in memory, hidden and inert until an authorized clinical read succeeds. Its captured episode and visit still control saving. Patient, real session username/role/permissions and existing external authority changes replace the workspace; presentation-only display-name refreshes preserve the draft and pending authorized reads. Layout cleanup retires the previous lifetime before paint, and retained old handlers check that lifetime and current clinical/case/plan grant before dispatching work. Read generations and abort signals reject superseded headers and bodies.

## Evidence and release boundary

- Focused component regressions cover denied headers from either endpoint with never-resolving error JSON, case denial during pending clinical headers or body and after clinical restoration, late peer success after denial, pending successful case JSON, clinical network/JSON/envelope/foreign-patient failures, ordinary failed case reads, preserved draft retry, newer-read supersession and real-session/patient A→B→A transitions. Captured saves from retired owners send no requests.
- Six deferred regressions cover case 401/403/404 after a failed or pending clinical save. Temporarily restoring the old shared mutation/read counter makes the two case-403 variants fail because the denial panel never appears; restoring the actual source byte-for-byte retains the corrected behavior.
- The built-app browser journey uses a fresh synthetic patient, case and open visit in the existing isolated security database. Only explicit fault responses are substituted. A single intentionally rejected save exposes the actual refresh control; clinical 403 is then verified before stalled case headers are released. Retry restores the original clinical/radiographic draft while failed cases remain unavailable, followed by an actual authorized read. The database's complete clinical visit/ENDO-record/invoice/payment rows must remain unchanged throughout.
- Exact 1280/390 denial-panel screenshots and five-point retry-control geometry are uploaded as `endodontics-reference-read-safety-ui`. This evidence is bounded to the synthetic denial panel; it is not a whole-page zero-occlusion claim or Production authentication proof.

Local focused unit tests, nonincremental TypeScript and scoped lint are required before publication. Exact-head full CI, browser evidence inspection and final review remain release gates. No database/schema/financial arithmetic/permission core or canonical procedure/signing engine is changed. Exact-item ENDO-to-procedure handoff and tooth-specific radiograph associations remain separate unfinished work.
