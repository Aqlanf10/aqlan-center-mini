# Reception call identity: release boundary

The public display no longer receives or renders aggregate operational statistics. The current legacy call, limited upcoming list and chair cues still use the existing masking policy. Individual rows may imply occupancy: do **not** describe the legacy feed as anonymous. This release does not add full names, a new credential, a new permission or a ticket system.

## Next release: gates, not active settings

1. Keep the internet-facing welcome screen separate from a **paired, in-clinic TV**. Before introducing selectable identities, move identifiable calls, speech, appointment lists and chair occupancy off the public response. Public/unpaired, expired and revoked devices get welcome/approved notices only. No hidden name, speech string, identifier, event or room-routing metadata in their JSON, HTML, logs, cached responses or client bundles. Pairing is explicit on site, per device, narrowly scoped, expiring and revocable; the TV does not gain staff access. Clear stale identifying content when authority expires or contact with the server cannot be revalidated.
2. Verify the actual clinic owner's identity on the server for configuration; generic administrator or settings access alone is insufficient. Audit the setting change, not patient names. Configure **visual identity and spoken identity separately**. Visual: exact registered name (no reordering, normalizing or truncating the data), existing abbreviated form, or issued daily ticket. Audio: muted, abbreviated, daily ticket, or separately opted-in registered name. Send only the authorized strings. Do not use a hidden full name for abbreviation or speech. Never announce a name when ticket-only privacy is selected; ticket-only defaults to ticket or mute. In all modes, only use local Arabic speech with sound enabled on the device; otherwise preserve the visual cue and chime.
3. Make the ordinary **successful reception check-in** allocate one stable short ticket for a visit in the clinic's local day. The owner’s example is a printed slip, not an app-only position. Unique per clinic/day, transaction-safe under concurrent arrivals, idempotent on retry, same on reprint. Preserve existing consultation, queue order, visit and payment rules. Handle exhausted ranges, midnight/reprints and printer failure explicitly; no extra check-in or duplicate financial movement. Print only the public ticket, clinic/date and relevant instructions. Never use the patient's permanent file number, visit ID, phone digits, array index or changing portal queue position.
4. Default a paired screen to ticket-only **after** ordinary check-in issuance/printing is proven. With no issued valid ticket, do not invent one or substitute a name; refer to reception. Before enabling opt-in named modes, prove with synthetic records: exact-name fidelity; abbreviation, missing names, duplicate abbreviations and ticket-only behavior; separate voice/mute choice; revoked device clears pending speech and stale identity; first fresh versus existing calls, recall and chime fallback; ordinary check-in/reprint at the printer. No patient data in fixtures. Existing staff metrics stay in authorized workflows, not in either lobby feed.
