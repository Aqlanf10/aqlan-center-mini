# عقد البيئة وتكافؤ CI — TD-02

> **المصدر الواحد للحقيقة البيئية.** كل ثابتٍ تعاقدي هنا له موضع تنفيذ حيّ:
> `lib/env-contract.ts` (الفحوص)، `package.json` engines + `.nvmrc` (Node)،
> `.github/workflows/ci.yml` (الفرض)، `docker-compose.yml` (قاعدة 18 المحلية)،
> و`npm run verify:environment` / `npm run verify:full` (البوابتان).
> اختبارات `__tests__/environment-parity.test.ts` تُسقط `npm test` عند انجراف أي
> ملفٍّ من هذه عن العقد.

## الغرض

قبل TD-02 كان «البناء يعمل عندي» لا يعني «البناء يمرّ في CI»: إصدار Node غير
 مثبَّتٍ محليًّا، وnpm يختلف بين CI وDocker، وقاعدة الاختبار أيَّ إصدار PostgreSQL
 يصادف الجهاز، ولا أمرًا واحدًا يُشغّل البوابات الإلزامية كلها محليًّا. هذا
العقد يجعل الجواب معروفًا **قبل** فتح PR:

```bash
nvm use                                   # ‎.nvmrc ⇒ Node 22
docker compose up -d pg18                 # قاعدة PostgreSQL 18 (المنفذ 54329)
DATABASE_URL=postgresql://ci:ci@127.0.0.1:54329/postgres?sslmode=disable \
TEST_DATABASE_URL=postgresql://ci:ci@127.0.0.1:54329/aqlan_p1_test?sslmode=disable \
  npm run verify:full                    # البوابة الكاملة — كل بوابة CI أساسية
```

**الرابطان دوران مختلفان لا بديلان** (تصحيح مراجعة المالك): `TEST_DATABASE_URL`
قاعدة **اختبار التكامل** (`aqlan_p1_test`) — تقرؤها اختبارات PostgreSQL الحقيقية
واختبارات الأمن وبيان خط الأساس؛ و`DATABASE_URL` قاعدة **الصيانة** (`postgres`)
— تقرؤها الرحلات التشغيلية حصرًا (كل رحلةٍ تنشئ قاعدتها المؤقتة بنفسٍ فريد
وتهدمها) وتوليد عقد المخطط. من ضبط رابط الاختبار وحده اجتاز الفحص المسبق
ثم رأى الرحلات تتخطى — فالفحص المسبق يطالب بالرابطين معًا الآن. والهدم الكامل
مع حذف الـvolume: `docker compose down -v` بلا اسم خدمة (`down` لا يقبل
وسيطة خدمة أصلًا).

## عقد Node (TD-REG-019)

- **المدعوم: Node 22 حصرًا** — `">=22 <23"`.
- المواضع الأربعة تُفحَص ضد بعضها آليًّا: `package.json` engines، `.nvmrc`،
  `ci.yml` (`setup-node`)، `Dockerfile` (`FROM node:22-alpine`).
- `npm run verify:environment` يرفض أي major آخر برسالةٍ تحمل الإصلاح
  («nvm use»)، واختبار `environment-parity` يثبت أن 23/24 تُرفض و22 تمرّ.
- لا ترقيةَ إلى major آخر ضمن TD-02 — هذا عملُ تكافؤٍ لا عملَ ترقية.

## عقد npm / مدير الحزم (المرحلة C)

- **المدعوم: npm 10.9–11** — `">=10.9 <12"` في engines.
- الحقيقة المادية التي يوثّقها العقد: صورة `node:22` تُدمج npm 10.9 — يكفي
  للبناء من القفل (`npm ci`) الذي هو سلوك تثبيت مستقر بين 10/11؛ وCI يرفع
  صراحةً إلى **npm 11** لأن بوابة التدقيق تعتمد نهاية الـbulk advisory التي
  يستدعيها npm 11 فقط (نهاية quick-audit المتقاعدة تُجيب 400 — موثَّق في
  `ci.yml`). رفعُ CI مقيَّد بمajor معلن (`npm@11`) لا `npm@latest`.
- `package-lock.json` يبقى المرجع الوحيد، و`npm ci` طريق التثبيت النظيف
  الوحيد في CI وDocker معًا. لا churn في القفل أُجري ضمن TD-02.
- الترقية إلى major أعلى (12+) ليست ضمن TD-02 وتحتاج قرار مالك مستقل.

## عقد PostgreSQL (TD-REG-008)

- **عقد الاختبار/التطوير: PostgreSQL 18 حصرًا.** هذا عقدٌ مستقل بذاته ولا
  يدّعي إثبات إصدار قاعدة الإنتاج على Railway — ذاك خارج المستودع لا يُرى
  من هنا (لا نافذة ادّعاء بلا دليل طازج).
- الفرض:
  - CI: خدمة `postgres:18-alpine` (باقية كما كانت).
  - المحلي: `docker compose up -d pg18` — نفس الصورة، نفس الحساب (ci/ci)،
    نفس القاعدة (aqlan_p1_test)، منفذ مضيف 54329 لتفادي الاصطدام بقاعدة
    محلية سابقة.
  - البوابة: `__tests__/postgres/_global-setup.ts` يفحص `server_version_num`
    **قبل كل ملفات الجولة** ويفشل برسالةٍ تحمل العقد وطريق الإصلاح عند أي
    major آخر — لم يعد «16 محليًّا يكفي» قولًا ممكنًا.
  - `npm run schema:contract` يفحص الإصدار قبل الكتابة: ملف `.pg18.json` لا
    يُولَّد من خادمٍ آخر (كان يكتب بلا فحص).
  - `db:baseline:manifest:verify` كان يرفض غير-18 أصلًا — كما هو.
- **دليل حيّ من الإغلاق نفسه:** الملف الملتزم `schema/current-schema-contract.pg18.json`
  كان مولَّدًا على **PostgreSQL 16.13** (`generatedOnServerVersion` في النسخة
  السابقة) وفارًا 5 جداول عن الحقيقة — أي أن اسمه كان كاذبًا وتغطية رحلة
  `verify:schema` ناقصة بلا فشلٍ يُبلّغ. أُعيد توليده على 18.4 ضمن TD-02
  (61 جدولًا · 742 عمودًا) والرحلة تمرّ عليه كاملًا. وبيان baseline
  الملتزم تطابق بصمتُه مع توليد 18.4 الطازج (`ea78837c…`) — إثباتُ أن
  المسار المحلي وCI يخرجان الحقيقة نفسها حين يكون الإصدار واحدًا.
- PGlite (in-process) ليست بديلًا عن هذه القاعدة: التزامن والاستعادة
  والاستدلالات الحقيقية لا تُثبت إلا على PostgreSQL حقيقي (فلسفة P1.3).

## عقد التوقيت (المرحلة E)

- **`CLINIC_TIME_ZONE=Asia/Aden`** — معناه الواحد موثَّق في `lib/clinicZone.ts`:
  منطقة IANA معروفة تُمرَّر كما هي؛ المجهولة أو الغائبة تُردّ إلى
  `Asia/Aden` (لا تُمرَّر فتُطفئ `Intl` كل حساب اليوم).
- CI يضبطها صراحةً و`verify:environment` يفرضها حرفيًّا في سياق CI؛ محليًّا
  الافتراض كافٍ ومنطقةٌ معروفة أخرى تمرّ (فرعٌ مستقبلي مشروع — لا يُمنع).
- الطوابع الزمنية المخزَّنة تبقى كما هي (UTC داخلية) — TD-02 لا يعيد هندسة
  تخزين الطوابع؛ هذا عقدُ قراءةٍ وصياغةٍ للحدّ اليومي فقط.

## البوابة المحلية الكاملة (TD-REG-013)

`npm run verify:full` — منسّق `scripts/verify-full.mjs`. الفحص المسبق يطالب
بالرابطين معًا (انظر أعلاه) ويرفض `USE_LOCAL_DB=true` وكل رابط غير آمن عبر
**كل مسارات الاتصال الحية** — لا اسمين فقط.

الخطوات — كل بوابة CI أساسية فاشلةٍ بذاتها، بترتيب CI نفسه:

1. `verify:environment` (عقد البيئة)
2. `typecheck`
3. `lint`
4. `test` (وحدة)
5. `test:postgres` (18 إلزامي)
6. `schema:contract` — توليد عقد المخطط الحالي على PostgreSQL 18 (فحص major
   قبل الكتابة)؛ بعد التوليد يُستعاد الملف الملتزم وتُحفظ النسخة الطازجة في
   مجلد أثرٍ مؤقت — عين سلوك CI بلا اقتلاع عملٍ غير ملتزم
7. `schema:contract:verify` — **بوابة أمان**: مطابقة النسخة الطازجة المحفوظة
   في مجلد الأثر بالملف الملتزم **بنيويًّا حرفيًّا** (canonical) — أي فرق
   جدول/عمود/نوع/قابلية عدم/قيد/إشارة/فهرس/مُشغّل/عدّاد يُفشل البوابة بـ
   `SCHEMA_CONTRACT_DRIFT`. مصدر minor للخادم (18.4 مقابل 18.6) لا يُفشل
   وحده — major 18 واحد والبنية هي المقيس. عين ترتيب CI: المقارنة قبل
   استعادة الملتزم فوق شجرة العمل
8. `verify:ci` (الرحلات — وتشمل رحلة `verify:schema` التي تطابق البناء
   الطازج بالعقد الملتزم بمجموعة جزئية — حماية مستقلة باقية كما هي)
9. `db:baseline:manifest` — توليد بيان خط الأساس المرشّح إلى ملف مؤقت خارج
   المستودع
10. `db:baseline:manifest:verify --fresh` — **بوابة أمان**: مطابقة البيان
    الملتزم ضد التوليد الطازج (ليست خطوة رفع أثر)
11. `ci:audit`
12. `ci:scan:body`
13. `build`
14. `test:security-http` (خلف البناء)

- **لا تخطيًّا صامتًا:** غياب قاعدة/Chromium فشلُ متطلباتٍ مُعلَّن السبب؛
  وسقوط خطوةٍ يوقف البوابة ويعلن المتبقي.
- **ليست بديلًا عن CI:** تبقى خطوات CI مرئيةً فرادى للرصد — البوابة الكاملة
  للتكافؤ المحلي، وعقد القائمة نفسه يُفحص اختباريًا ضد `ci.yml` فلا تختفي
  بوابةٌ من الطرفين دون سقوط `npm test`.

## مصفوفة CI مقابل البوابة المحلية — فصلٌ صريح (تصحيح مراجعة المالك)

كل خطوة في `ci.yml` إما بوابة جودة أساسية لها مقابلٌ في `verify:full`، أو
خطوة منشأ/أثر CI-only لا معنى لها محليًا — لا ثالث بينهما:

| خطوة CI | في verify:full | الصنف |
|---|---|---|
| `npm ci` + رفع npm إلى 11 | الفحص المسبق يتحقق من عقد npm | تجهيز بيئة |
| `verify:environment` | ✓ خطوة 1 | **بوابة أساسية** |
| `typecheck` / `lint` / `test` / `test:postgres` | ✓ خطوات 2–5 | **بوابة أساسية** |
| توليد عقد المخطط على PostgreSQL 18 | ✓ خطوة 6 (مع استعادة الملتزم) | **بوابة أساسية** (فشل ذاتي: فحص major والبناء والاستدلال) |
| تحقق انحراف عقد المخطط (الملتزم مقابل الطازج) | ✓ خطوة 7 | **بوابة أمان أساسية** (`SCHEMA_CONTRACT_DRIFT`) — قبل استعادة الملتزم في الطرفين |
| رفع أثر عقد المخطط | نسخة إلى مجلد أثرٍ مؤقت يُطبع مساره | أثر/مصدر CI-only |
| `verify:ci` (الرحلات) | ✓ خطوة 8 | **بوابة أساسية** |
| توليد بيان خط الأساس المرشّح | ✓ خطوة 9 (إلى ملف مؤقت) | **بوابة أساسية** |
| تحقق البيان الملتزم ضد الطازج | ✓ خطوة 10 | **بوابة أمان أساسية** |
| رفع أثر البيان المرشّح | يبقى الملف المؤقت للفحص اليدوي | أثر/مصدر CI-only |
| `ci:audit` / `ci:scan:body` / `build` / `test:security-http` | ✓ خطوات 11–14 | **بوابة أساسية** |
| تثبيت Chromium | فحص مسبق (يتحقق من وجوده ويشرح تثبيته) | تجهيز بيئة CI-only |
| رفع لقطات إعدادات الواجهة | — | أثر CI-only (`if: always()`) |

قاعدة الفحص المرافقة: `REQUIRED_CI_GATES` تشمل الآن `schema:contract` و
`schema:contract:verify` و`db:baseline:manifest` و`db:baseline:manifest:verify` —
اختفاء أيٍّ منها من `ci.yml` أو من خطوات البوابة الكاملة (أو خرق ترتيبها)
يسقط `npm test`.

## CI — عقد عدم الاختفاء (المرحلة H)

- خطوة `Verify environment contract` تُشغَّل بعد `npm ci` مباشرة — أي انجراف
  بين ملفات العقد نفسها يفشل البناء قبل إنفاق دقائق البوابات.
- البوابات الإلزامية مفهومة اختباريًا في `REQUIRED_CI_GATES` ويُثبت وجود كلٍّ
  منها في `ci.yml` (بالأمر أو بأمره التحتّي الحرفي) — إزالتُها سقوطُ `npm test`.
- روابط قواعد CI كلها `127.0.0.1` مع `sslmode=disable` — و`verify:environment`
  في سياق CI يرفض غير المحلي، ومضيفي Railway يُرفضون مطلقًا حتى مع تصنيف.
- **عقد المخطط يُقارن قبل أن يُستعاد:** توليد → حفظ الطازج في `/tmp` →
  `schema:contract:verify --fresh … --committed` (الملتزم من `git show HEAD:` —
  فشل `SCHEMA_CONTRACT_DRIFT` عند أي فرق بنيوي) → `git checkout --` استعادة
  الملف الملتزم فوق شجرة العمل → رفع الأثر. ترقية minor لصورة الخادم
  (18.4 → 18.6 مثلًا) لا تُفشل وحدها؛ البنية هي المقيس.
- لا `secrets.*` في الـworkflow ولا وصول لقاعدة إنتاج؛ artifacts الرفع لا
  تعدّل ملفات ملتزمة (عقد المخطط يُستعاد بـ`git checkout --` بعد النسخ والتحقق).

## Docker — بناء وتشغيل (المرحلة I)

- صورة واحدة عبر المراحل الثلاث: `node:22-alpine` — العقد نفسه الذي يفرضه
  CI وengines (مفحوص اختباريًا).
- التثبيت: `npm ci` من القفل بnpm المدمج (10.9) — ضمن عقد npm أعلاه؛ لا
  بوابة تدقيق داخل Docker (هي بوابة CI/محلي).
- التشغيل: مستخدم غير جذر (`su-exec nextjs`)، `NODE_ENV=production`،
  `PORT=3000`، `HOSTNAME=0.0.0.0`، Standalone server.
- **لا هجرة عند الإقلاع** — ملفات الهجرة لا تُنسخ إلى الـrunner (عمدًا؛
  الملكية لاحقًا في TD-01A/TD-01B).

## عزل بيئة الاختبار (المرحلة K — نتيجة التدقيق)

مفحوص وموجَد سليم أصلًا: اختبارات PostgreSQL تستخدم قواعد معزولة تُنشأ وتُهدم
لكل ملف (`_setup.ts`)؛ اختبار الأمن HTTP ينشئ `aqlan_sec_http` ويسقطها؛
الأدلة المؤقتة `mkdtemp` لا مجلدات مشتركة؛ منفذ الأمن قابل للتهيئة
(`SECURITY_HTTP_PORT`) لا شاغلًا ثابتًا؛ لا اتصال إنترنت خارجي في الاختبارات
ولا متغيرات Railway. التصحيحان الوحيدان اللذان احتاجهما العزل البيئي ضمن
TD-02: **فحص major لقاعدة الاختبار** (أعلاه) و**فحص عقد البيئة قبل البوابات**
— كلاهما «فشلُ بيئةٍ مُعلَن» لا «فشل منطقٍ غامض». ميزانيات المهلات الصريحة
للاختبارات الثقيلة بالإدخال/الإخراج (مثل 30 ثانية لاختبار سجل النسخ
بـ505 كتابة ذرّية) مقبولةٌ تعاقديًا بلا مساسٍ بالتوكيدات.

## ما قبل TD-02 (الحالة «قبل» المختصرة)

- لا `engines` ولا `.nvmrc` — إصدار Node اتفاقٌ شفهي؛ جهازٌ على 24 وجهازٌ
  على 22 يبنيان «نفس المستودع» بنتائج غير مضمونة التطابق.
- npm 11 في CI مقابل npm المدمج في Docker مقابل أي npm محلي — بلا عقدٍ مكتوب.
- `test:postgres` يقبل أي إصدار خادم — نجاحٌ محلي على 16 لا يعني شيئًا عن 18.
- `schema:contract` يكتب `.pg18.json` من أي خادمٍ يصادفه `DATABASE_URL`.
- لا أمر بوابةٍ محلية واحد؛ التخطي الصامت ممكن بلا قصد.
- لا تصنيف مرجعي لمتغيرات البيئة (قواعد الأسرار مبثوثة في تعليقات متفرقة).

## خارج نطاق إثبات هذا الملف

- إصدار قاعدة الإنتاج على Railway وبيئاته المتغيرة — لا دليل طازجًا من
  المستودع، فلا ادّعاء (انظر عقد PostgreSQL أعلاه).
- ترقية Node إلى major آخر، ترقية npm إلى 12+، وإعادة هندسة تخزين الطوابع —
  قرارات مالك مستقلة عن TD-02.
