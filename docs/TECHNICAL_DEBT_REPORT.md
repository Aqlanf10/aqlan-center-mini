## 2. تفاصيل المعالجات المنجزة (Detailed Technical Interventions)

### 2.1 معالجة تحذيرات Turbopack و Dynamic Filesystem Tracing في `lib/files.ts`

* **التشخيص:**
  عند تشغيل أمر البناء `next build` باستخدام محرك Turbopack في Next.js 16.3.3، كانت تظهر 4 تحذيرات تفيد بأن استدعاء دوال نظام الملفات الديناميكية مثل:
  - `stat(path)`
  - `join(status.directory, key)`
  - `readFile(join(status.directory, key))`
  تتسبب في قيام المحلل الثابت بتتبع (Tracing) كامل مجلدات وملفات المشروع ومجلد `public/` وضمها كحزم على الخادم، مما يؤدي إلى تضخم حجم حزمة النشر الإنتاجية وإبطاء عمليات النشر ورفع زمن استجابة الحاويات المؤتمتة على Railway.

* **الحل المعماري:**
  - تم تضمين توجيهات التجاهل المباشرة لمحرك Turbopack `/*turbopackIgnore: true*/` في جميع مواضع قراءة وفحص وكتابة المسارات الديناميكية داخل [lib/files.ts](file:///C:/Users/Aqlan%20Alkamel/.gemini/antigravity/scratch/aqlan-center-mini/lib/files.ts) (`stat`, `join`, `readFile`, `writeFile`, `mkdir`).
  - عزل تتبع القرص الدائم الملحق (`DOCUMENTS_DIR`) عن التجميع الثابت للكود المصدري للتطبيق.
  - الحفاظ التام على الحماية ضد فقدان الأشعة الصامت (Silent Data Loss Prevention) وفق المبدأ الثامن من المحظورات (منع تخزين الأشعة الثقيلة في قاعدة البيانات وتوجيهها للقرص الملحق المدار).

### 2.2 توحيد وضبط ملفات تهيئة الاختبارات (`vitest.config.mts`)

* **التشخيص:**
  مشروع `package.json` غير معرّف كـ `"type": "module"`. بالتالي، كان وجود `vitest.config.ts` بصياغة ES Modules يطلق تحذيراً بارزاً من محرك Vite:
  ```text
  (!) Your Vite config uses features that are unsupported by `configLoader: 'native'`, which is planned to become the default in a future major version of Vite:
    - ESM syntax in a file loaded as CommonJS (vitest.config.ts:1:1). Use a `.mjs` extension or set `"type": "module"` in the closest package.json
  ```
  وكان هذا يشير إلى اعتماد مؤقت على المحمل القديم وسقوط وشيك في الإصدارات المستقبلية لـ Vite.

* **الحل المعماري:**
  - نقل كامل التهيئة إلى ملف موديول صريح الامتداد: [vitest.config.mts](file:///C:/Users/Aqlan%20Alkamel/.gemini/antigravity/scratch/aqlan-center-mini/vitest.config.mts).
  - حذف الملف القديم `vitest.config.ts` نهائياً لمنع أي تنازع في تحميل الإعدادات أو ارتباك أداة التحميل.
  - إعادة تشغيل الاختبارات والتأكد من اختفاء التحذير تماماً وعمل المحمل الأصيل (Native loader) بسرعة ودقة.

## 4. الامتثال للمبادئ الخمسة والمحظورات العشرة (Constitutional Alignment)

1. **One Patient — One Record:** لم تتأثر أي واجهات استعلام أو كيانات مرتبطة بسجل المريض الموحد.
2. **One Clinical Workflow:** تكامل الزيارات والمخطط السني FDI والخطط العلاجية يعمل دون أدنى تغيير في التوقيعات أو الواجهات.
3. **One Financial Source of Truth:** سندات القبض والصرف، ورديات الصندوق، وعزل العملات (YER / SAR / USD) تظل حصينة وغير قابلة للتعديل أو الحذف، ولم يُمس أي منطق مالي أو حسابي.
4. **Central Business Rules:** استمرارية تركيز منطق الأعمال على الخادم في `lib/` ومنع تشتيته.
5. **One Auditable History:** تدفق سجلات التدقيق (Audit Log) مؤمن بكامل تفاصيله.

## 5. توصيات الصيانة المستقبلية (Maintenance Guidelines)

1. **التعامل مع ملفات النظام الديناميكية:**
   عند إضافة أي استدعاءات لمكتبة `fs` للتعامل مع مسارات تخزين متغيرة وقت التشغيل (مثل مجلد النسخ الاحتياطي أو التصدير)، يجب دائماً تزويد الاستدعاء بـ `/*turbopackIgnore: true*/` لحماية الحزمة الإنتاجية من احتواء ملفات غير مرغوبة وتفادي تحذيرات الحزم.
2. **ملفات التهيئة في بيئة Node الهجينة:**
   نظراً لأن المشروع لا يعتمد `"type": "module"` في `package.json` الرئيسي لدواعي التوافق مع بيئات النشر والأدوات، يجب دائماً استخدام الامتداد الصريح `.mts` لملفات إعدادات الأدوات التي تعمل بصياغة ESM (مثل Vitest أو أدوات التهيئة الجديدة) لضمان التوافق مع معايير Vite و Node المستقبلية.
