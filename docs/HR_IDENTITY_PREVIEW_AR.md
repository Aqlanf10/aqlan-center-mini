# معاينة هوية الطاقم — الشريحة الأولى فقط

الأساس: `main@928bb7e5d140797c8654fc59016b3beb02acbb14`، بعد PR336. الفرع الوحيد لهذه الشريحة: `feat/hr-identity-preview-20261016`.

التنفيذ يضيف تبويب «معاينة الهوية» داخل HR للمدير الحالي. يعرض معرفات الحسابات وملفات HR وجهات doctor/employee، وروابط الحساب والملف والعقد ومراجع المسير السابقة، والبيانات غير الموثقة والتعارضات. لا يقرأ مبالغ أجور أو نسبًا أو commission_config ضمن بيانات المعاينة، ولا يستنتج الهوية من الاسم.

`GET /api/hr/identity-preview` يعرض المصادر. `POST` لنفس المسار **تحليل قرائي** لا حفظ: يتلقى اختيارًا مؤقتًا بمعرفات صريحة وتأكيد أنها للشخص نفسه، ويعيد create/link/skip/conflict. لا endpoint للتطبيق ولا أمر حفظ، ولا بيانات في localStorage أو sessionStorage. create يعني اقتراح هوية غير مكتملة في مرحلة لاحقة؛ لا حساب/جهة/عقد أو تاريخ توظيف مفترض. لا تُضاف حسابات متعددة للشخص تلقائيًا لمجرد اشتراك الجهة. المورد والمختبر لا يظهران كمرشحي موظفين؛ إن أشار إليهما رابط غير متوافق يعرض التعارض دون اسم الجهة المستبعدة.

المراجع المخزنة ليست دليل شروط تعاقد: الحالة المخزنة تُعرض كحقيقة مصدر، وغياب عقد approved/active أو تاريخ التوظيف يظهر صراحة. الأعداد هي أعداد مرشحين/قرارات، وليست تعداد أشخاص محسومًا. الروابط التاريخية المالية تبقى كما هي؛ اختلاف جهة الحساب والعقد والصرف يحال للمراجعة. البصمة تخص حقول الهوية المعروضة فقط، وليست بصمة مالية أو موافقة ترحيل قابلة للتنفيذ.

الخدمة تعمل داخل `REPEATABLE READ READ ONLY` مع projection صريح. تقرأ الجلسة الموقعة ثم تتحقق من الحساب الحالي والنشاط والدور ومعرف الحساب ونسخة الاعتماد دون `requireSession()` العام الذي قد يشغّل ensureSchema. password_hash يُقرأ داخل فحص الاعتماد فقط ولا يدخل المصادر أو الاستجابة أو digest. لا SELECT FOR UPDATE/SHARE ولا nextval ولا audit writer أو commission resolver أو إنشاء مخطط. نقص جدول يفشل مغلقًا503، ولا يصلح القاعدة. هذا ضمان لمسار المعاينة الجديد؛ لم تُعدّل آليات إقلاع التطبيق أو المسارات القديمة التي قد تستدعي ensureSchema، وإصلاح مطابقة الاسم فيها مؤجل.

الحد1000 سجل لكل مجموعة مصادر؛ تجاوزه يرفض المعاينة كاملة503 بدل تقرير جزئي. قرارات المعاينة محدودة20 وبحد30 معرفًا لكل قائمة، ومقيدة بحجم قارئ JSON. المعرّفات المفقودة أو الروابط المتعارضة تعرض conflict، بينما JSON غير صالح أو حقول إضافية تُرفض400. تغير مصادر الهوية بين العرض وPOST يرفض409 ويطلب تحديثًا. الاستجابة غير قابلة للتخزين المشترك (`private, no-store`). تحديث المصادر يمحو الاختيار المؤقت. تبديل الحساب/التبويب يلغي القراءة ويمنع ردًا متأخرًا من إعادة بيانات قديمة.

الملفات الأساسية: `lib/hr-identity-preview-shared.ts` للـDTO الآمن، `lib/hr-identity-preview.ts` للتصنيف والتحقق والبصمات، `lib/hr-identity-read.ts` للقراءة والتفويض، route الجديد، `components/hr/IdentityPreviewPanel.tsx` وتسجيل التبويب والمصفوفة. يسجل `lib/audit-coverage.ts` سبب تصنيف POST كمعاينة قرائية، مثل المعاينات الأخرى الموجودة؛ لا تغيير للحارس أو اختباراته ولا تدقيق نجاح كاذب لعملية حفظ. لا migrations أو تغيير مخطط أو users/parties/HR/finance writer أو grants. لا تغيير Staging أو تقويم أو مخزون أو AI/Dot أو CSS مشترك.

الاختبارات المضافة:

- Unit: حسابان بنفس الاسم دون دمج تلقائي ثم قرار صريح لشخص واحد، جهة طبيب بلا حساب، استقبال وHR ناقص، مورد مستبعد، تعارض ملفات وجهات وروابط مفقودة، تكرار قرارات، ثبات البصمة، منع الحقول الحساسة/غير المسموحة.
- PostgreSQL: وضع READ ONLY الفعلي لكل SELECT، مقارنة بصمات **كل** جداول public وحالة **كل** التسلسلات قبل/بعد GET/service review، بقاء الطبيب غير المربوط كما هو، رفض stale/expired/revoked/inactive/changed-role، تعارض عقد، ونقص مخطط دون إصلاح.
- HTTP ومتصفح390/1280: حارس المدير ورفض بقية الأدوار والجلسة الغائبة وطرق الكتابة الأخرى، اختيار IDs وتأكيد مؤقت، صفر تغير في الجداول والتسلسلات، عدم ظهور أسرار أو مسودة نسبة، تحديث يمحو القرار، عدم تجاوز عرض الصفحة، وصور وأخطاء متصفح.

هذه الشريحة لا تنفذ جدول الروابط المتعددة أو منع الاعتماد بالحساب الثاني أو نموذج الشروط المجهولة أو ربط الإدارة السريري أو التفويض canonical. تفاصيل المرحلة التالية والاختبارات المقترحة موجودة كاملة في [التصميم المعتمد للمراجعة](HR_IDENTITY_UNIFICATION_DESIGN_20261016_AR.md). تلك المراحل تحتاج تنفيذًا ومراجعة مستقلة؛ وجود التصميم هنا ليس ادعاء تفعيلها.
