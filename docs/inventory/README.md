# Inventory implementation checkpoint

This feature branch is a review checkpoint, not an enabled release. New procurement/custody tables await coordinated migration registration. The application returns503 `schema_not_ready` when those tables are absent; it never creates them automatically. Do not run proposal SQL against a deployed database.

## User flows available in the synthetic fixture

- `/inventory/review`: administrator Arabic/English valuation, explicit missing/estimated costs, search/pages and complete branded report print. A missing acquisition price is never represented as known zero.
- `/inventory/procurement`: authenticated clinic requester submits several registered package quantities with a need reason (bilingual Arabic/English). The request changes no stock, supplier debt or cash. Administration can record a reasoned monetary revision and exact partial approval at `/inventory/procurement/review`, with explicit valuation/source and selected request print (bilingual Arabic/English). The owned `/inventory/procurement/operations` interface (bilingual Arabic/English) saves approved-source orders, versioned purchase-order amendments (`order.amend` preserving append-only order history), inspected partial receipts (with explicit excess-arrival decisions: `return_excess_to_supplier`, `hold_for_order_amendment` blocking quarantine release with `order_amendment_required` until order capacity is amended), quarantine lot resolutions (`release`, `reject_return`, `dispose` with `disposedBaseQuantity` tracked separately from `rejectedBaseQuantity`), historical legacy stock-to-lot reconciliations (`legacy.reconcile` deriving `requiresExpiry` from server records and failing closed to `true`), and inventory matching evidence. It creates no existing financial invoice, signed receipt, payable/payment or commission entry. Those integrations are deferred.
- `/inventory/custody`: administrators dispatch valid tracked lots between store/doctor locations through a distinct transit location. The receiving doctor or administrator confirms accepted quantities or inspected returns to source. In addition to transfers, `/inventory/custody` supports actual doctor custody usage/consumption (`custody.consume` linked to verified patient/visit/case/procedure and enforcing `doctorOwnsPatient` across all supplied clinical entities without double-counting), independent admin waste approval (`custody.approve_waste` stored in `custody_waste_approvals`), custody return to store (`custody.return_to_store`), physical custody stocktake & variance holding (`custody.stocktake`), server-verified safe empty-package / depletion closure (`custody.close_package` enforcing `classifyDefaultPackageSafety` / `resolvePackageSafetyWithFieldObservation` without hazard downgrade, verifying `packageId` and `evidenceEventId` against authoritative DB records, and supporting multi-tranche lot closures), and annual `D − A` settlement review proposals and immutable doctor objections (`custody.propose_settlement`, `custody.object_settlement` with canonical `YYYY-annual` period normalization and `postedEntryId` verification) without automatic debt, salary deduction, or voucher creation.
- Custody Arabic/English print shows allocated quantities, unavailable stock and safety instructions. It is not a financial settlement. Sharps/contaminated material must never be returned to storage or retrieved from waste for counting/photos.
- Read-error & audit hardening: database read failures never degrade to `0` stock or empty arrays (`readFailure` / HTTP 503 `inventory_read_failed`), and allowlisted `safeInventoryErrorMessage`, `publicInventoryErrorCode`, and `sanitizeInventoryAuditDetails` strip sensitive connection strings, secrets, cookies, constraint names, tokens, and raw SQL from responses and audit logs while logging structured `{ event: "inventory_api_error", correlationId, code: "inventory_unavailable", errorType }` diagnostics on 500 errors.
- If a write result is uncertain, inputs remain locked and the explicit confirmation button retries the identical command/key. Check the confirmed result before starting another operation.
