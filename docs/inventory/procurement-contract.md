## Actual implemented boundaries

- `quantities.ts`: strict decimal quantities against NUMERIC(12,3), item-specific immutable conversion/version snapshots, rejection of inexact conversion/zero/overflow. A package factor is never inferred from text.
- `procurement.ts`: content/version-bound full/partial approval, fixed currency approval valuations, cumulative approved-source order budgets/quantities, inspected receipt classification, exact three-way quantity/price match, shipping/discount apportionment and canonical payload identity. A domain plan is not a database commitment.
- `procurement-store.ts`: trusted actor re-read from users; single existing clinic scope; configured approval policy with no implicit limit; approved requests locked in sorted order; supplier active/kind checks; immutable registered package versions; transaction-level idempotency; order/receipt locks; accepted/quarantined/rejected classification; stock inserted into existing inventory_movements without supplier debt; true lots/locations referencing those movements; existing insertAuditRow in the same transaction. Audit failure rolls back stock and document effects. Identical retries return original result; changed content conflicts.
- Supplier invoice matching is persisted and reserves matched accepted quantities. It creates no payable or cash. `supplier_invoice_payable_links` is an append-only unique invoice→existing payable relation for the root-owned finance adapter. Existing inventory_movements_payable_uniq is not changed. No supplier order is sent.
- New command API rejects arbitrary status patches. Management commands are admin-only; requesters are admin/reception/doctor on this pinned base. Actor and clinic scope come from server validation; requestedBy in client JSON is overwritten from authenticated identity.
- New request UI uses registered package versions, supports several lines, preserves uncertain-operation keys across retries, withdraws stale reads, clears drafts on session-owner changes, and provides quantity conversion previews and paged request reads. It currently supports quantity-only requests. Monetary revision/approval/order/receipt/matching user interfaces and broader delegated capabilities are not complete.

## Quantities, money and audit ownership

inventory_movements is the clinic quantity source. Lot/location allocations reference it; there is no editable stored balance. Custody transfers must conserve clinic stock/value and never count as consumption. payables/expenses/payment allocations remain debt/cash sources. Receipt is not invoice and invoice is not payment. Doctor attribution is contractual consumed cost, not purchased/transferred stock. Applied material deductions net linked reversals determine D; theoretical materialRate is not substituted. No implicit payroll deduction or disciplinary debt.

The schema proposal includes immutable unit versions, locations and approval policies; request headers/revisions/lines/approval events; orders/lines/source allocations; receipts/lines; stock lots/movement allocations; supplier invoice match documents/receipt allocations/payable links; operation identities. It adds guards only to these new evidence tables and never removes existing guards. Existing audit_log and insertAuditRow are reused. The new action-specific audit enum is a root-owned follow-up; current transaction audit uses the existing inventory.item action with distinct entities/operation/version details.
