# مصفوفة صلاحيات HTTP (TD-04 / TD-REG-006)

**المصدر الواحد:** `lib/http-permissions.ts` — مدخلٌ لكل `app/api/**/route.ts` بكل فعلٍ يصدّره.

## لماذا

كانت الصلاحيات موزعة على 116 ملف مسار (236 فحصًا مضمّنًا) بستة أنماط حراسة مختلفة، ولا شيء
يمنع مسارًا جديدًا من النشر وهو بلا فحص، أو بفحصٍ أوسع من المقصود. المصفوفة تجعل من يصل إلى
ماذا **مسجَّلًا في مكانٍ واحد ومُثبتًا على التطبيق المبني**.

## معنى المدخل

| القيمة | المعنى |
|---|---|
| قائمة أدوار | الأدوار التي **قد** تجتاز حارس المسار (بأقصى صلاحيات المستخدم الفردية). الحارس يضيّق بعدها: ملكية المريض، صلاحيات المستخدم، البيانات. **الدور الغائب مرفوضٌ دائمًا.** |
| `PUBLIC` | بلا جلسة — قائمة `PUBLIC_API` في `proxy.ts` (الدخول، الإعداد، الصحة، شاشة الصالة، طلب الموعد، الاستعلام العام عن الطابور) |
| `PORTAL` | بوابة المريض — المسار يفحص جلسة البوابة الموقّعة |
| `SHARED_MEDIA` | وسائط الرسائل (صوت/مرفق) — للطاقم والمريض صاحب الخيط، والمسار يفحص الهوية **قبل** قراءة السجل |
| `WEBHOOK` | يطرقه مزوّد خارجي — حارسه التوقيع أو مفتاح الاستقبال |
| `INTERNAL` | مهام مجدولة بتوكن Bearer سرّي (`/api/internal/`) |

اختصارات الأدوار: `ADMIN` (المدير)، `CLINIC` (المدير والاستقبال والطبيب)، `FRONT_DESK` (المدير
والاستقبال)، `CLINICAL` (المدير والطبيب)؛ وما سواها قائمةٌ صريحة.

## كيف تُنفَّذ

1. **الباب مغلقٌ على ما لم يُسجَّل** (`proxy.ts`): طلب API بجلسة لمسارٍ غير مسجَّل ⇒ 404
   «هذا المسار غير موجود.»، ولفعلٍ غير مسجَّل ⇒ 405 مع `Allow` — قبل أي معالج. HEAD يتبع GET.
2. **فحص ثابت في CI** (`__tests__/http-permissions.test.ts`):
   - كل `route.ts` له مدخل، وكل مدخل له `route.ts`، والأفعال متطابقة تمامًا؛
   - قائمة `PUBLIC_API` في الباب = مدخلات `PUBLIC`/`PORTAL`، وبادئات المرور العامة = `SHARED_MEDIA`/`WEBHOOK`؛
   - كل مسار طاقم يستدعي حارس جلسة معروفًا؛
   - المدير في كل قائمة أدوار؛
   - الكاشير والمحاسب والمساعد لا يُسجَّلون على مسارٍ ترفضه قائمة السماح في `lib/role-routes.ts`.
3. **فحص حي على التطبيق المبني** (`__tests__/security-http/http-permission-matrix.test.ts`):
   لكل مسار وفعل، كل دورٍ غائب — بأقصى صلاحياته (طبيب بكل صلاحيات المدير، كاشير ومحاسب بكل
   مفاتيح المالية) — يُرفض 401/403 **برسالة عربية**؛ والمجهول مرفوض على كل مسار غير عام؛ وجلسة
   البوابة لا تفتح مسار طاقم.

رسائل الرفض العربية الدقيقة («… للمدير وحده») تبقى في المسارات نفسها — يعتمد عليها المستخدم
والاختبارات؛ فالباب لا يكرر فحص الدور (لا تغيير لأي رسالة أو حالة قائمة).

## إضافة مسار جديد

1. اكتب المسار بحارسه (`requireSession` + فحص الدور، أو `guardPatient`، …).
2. أضف مدخله في `lib/http-permissions.ts` بالأدوار التي يقبلها حارسه فعلًا.
3. إن كان لدورٍ محروس عند الباب (كاشير/محاسب/مساعد) فأضفه أيضًا إلى قائمة سماحه في `lib/role-routes.ts`.
4. `npm run test` يتحقق من الاكتمال، و`npm run test:security-http` يثبت أن الأدوار الغائبة مرفوضة.

## ما كشفته المصفوفة عند بنائها

- **وسائط الرسائل** (`/api/messages/voice/[id]`، `/api/messages/file/[id]`) كانت تقرأ جسم الرسالة من
  القاعدة قبل فحص أي جلسة: المجهول يعرف وجود رسالةٍ برقمها (404 مقابل 401) ويُحمِّل الخادم جسمها.
  **أُصلح:** الهوية أولًا ⇒ 401 دون قراءة.
- `POST /api/patients/[id]/intake-history` لمريضٍ غير موجود يرد 500 بدل 404 — سُجّل لـ TD-06
  (عقود الأخطاء)، خارج نطاق الصلاحيات.
