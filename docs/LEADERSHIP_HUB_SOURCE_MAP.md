# Leadership hub: implementation scope and source ownership

Base: PR #472 commit `b0a0578361a31eb854ed9e64caaa2c5ba41ea080` (tree `6bfc22a0d57669c2a598b05bc97c51fffc44485c`), containing the earlier operational overview. This change is an isolated read-only UI and projection. It does not change those PR branches, business workflows, financial calculation, permissions, schema, Production or Staging.

## Design decision

The owner delegated expert selection and requested professional cards. Use a restrained Fluent-inspired work surface inside the existing application shell: clinic navy structure, the existing orange accent, the existing local IBM Plex Arabic, compact cards with real values and source-specific labels, and original-record drilldowns. This is not a Microsoft product/brand copy, a global rebrand or a new second operating surface.

Three layers: a concise overview, attention lists with evidence, then the canonical working record. No decorative charts, fake comparisons, empty department cards, rainbow status fields or new notifications. The read-only hub never assigns, calls, books, completes, accepts, sends or pays anything.

## UI and transport owners

- `app/executive/page.tsx`: authenticated workspace, local section selection, principal-keyed subtree. Existing privileged-doctor financial access remains separate from admin-only operational access. AppShell is unchanged.
- `components/leadership/LeadershipOverview.tsx`: selected-arrival-day pulse, current all-date lab preview, visible current task priorities and canonical links. Four cards are distinct: waiting visits, all unfinished visits, received-unfitted orders and overdue-at-lab orders. Waiting is explicitly a subset of unfinished, not an independent total to add.
- `components/leadership/LeadershipTeam.tsx`: task detail list and explicitly opened attendance/inventory readers. It does not manufacture a workforce denominator or live doctor presence.
- `components/leadership/ExecutiveFinancialOverview.tsx`: fresh four-view financial presentation with uniform currency cards and progressive detail, without changing formulas, endpoint, CSV, currency grouping or range semantics. Imported only when needed.
- Existing `LeadershipOperationalOverview` / `LabBacklogOverview`: existing full source-specific detail owners with the same reader behavior and newly unified card/control styling; mounted on demand rather than combined into one misleading date filter.
- `components/leadership/useLeadershipRead.ts`: no-store, no polling, timeout/abort, request-key clearing, late-result rejection, explicit unknown/error, manual refresh and stale-on-focus/reconnect. It is scoped to this hub, not a replacement for mutation hooks.
- `lib/leadership-pulse.ts`, `lib/leadership-pulse-db.ts`, `app/api/executive/pulse/route.ts`: strictly decoded admin-only day/tasks/care readers. One SQL statement per view, exact whole-population totals, stable ten-row page and bounded enrichment. Current authenticated principal is checked before and after the read. No financial readers or schema bootstrap in these projections.
- `leadership.module.css`: scoped semantic layout/accent. Existing global tokens, font, focus styling, icons, PageHeader, native date picker and natural document scrolling remain authorities.

## Loading and failure budget

Overview owns three initial requests only: selected-day pulse, current shared tasks and current lab backlog. Existing AppShell requests are unchanged and excluded from claims about this new budget. Finance, clinical care/reports, operational cohort, attendance and inventory are not fetched for initial overview. The selected day never filters the lab or task backlog. No new interval, unbounded event fetch, per-row request or per-doctor fan-out. Each source retains its own timestamp and errors; there is no fabricated global atomic snapshot or grand total across overlapping entities.

Source failure is unknown, never zero. Changing date/source or principal hides old values immediately. Focus/reconnect marks potentially stale and does not automatically issue more reads. Clicking a source record is navigation, not resolution. No patient data in URL filter state or browser storage. Default Today uses the server clinic day on each manual refresh, including after midnight. Choosing a date or paging a displayed cohort pins that explicit day; the Today control returns to server-today. The refresh control is explicitly labeled for operations and lab only; tasks have their own refresh. Future arrival timestamps produce unknown waiting age, not zero. A session denial in any new reader clears the whole new hub subtree.

## Deferred, not promised by the current sources

- Unified decision/approval inbox, automatic escalation, accepted/reassigned follow-up ownership and SLA policy.
- Automatic causal attribution of delay to staff, lab or patient; employee scores or disciplinary conclusions.
- Complete current workforce availability, expected attendance denominator and doctor presence.
- Exact lab-order-to-appointment/plan/invoice membership beyond existing verified linkage.
- New contact/reminder/provider workflows, outbound messages, finance writes, export redesign and new AI/Dot features.
- Broad global-shell redesign or whole-application accessibility certification.

## Verification contract

Unit/route tests: transport consistency, permission denial before read, role/account revocation, no-store, null due, temporal scope, no invented historical-visit link, financial integrity reader regressions. PostgreSQL: actual clinic-midnight boundaries, exact pagination beyond 300 tasks, privacy in totals, actor versus assignee, read purity, and a 20,000-task/100,000-event fixture with one statement and bounded enrichment. Hosted synthetic app: desktop and narrow RTL, keyboard, source failure/session clearing, date independence, no writes, first-paint request budget, real screenshots and performance entries. New evidence is uploaded as an explicit synthetic-only artifact, never logs or auth state.

Tests and screenshots are only claimed after their executions succeed. Hosted browser evidence remains a publication/CI gate; local Chromium restrictions are not bypassed.

## Completion pass from production-equivalent main `dc1be92e`

- The overview now shows scheduled-day appointment / no-show / cancellation counts already supplied by `LEADERSHIP_DAY_SQL`, separately from arrival-day visits. Review navigation carries that displayed day; lab cards carry `awaiting_fitting` / `overdue` filters. No extra overview read is added.
- Financial transport is now `useLeadershipRead` + `lib/leadership-financial.ts`: abort/20s timeout, synchronous request-key clearing, strict matching dates/native currencies/integer amounts, source failure as unknown, stale-on-focus, and global hub clearing on current 401/403. Invalid/reversed input dates make no request. The receipt timestamp is explicitly client receipt in UTC, not a fabricated database snapshot. Presets use the existing clinic fallback calendar rather than the workstation's day; there is no FX conversion or recomputation.
- `LeadershipClinicalOverview` loads clinical source readers only when its section opens. The exact current active-plan/pending-item projection uses the leadership pulse reader; optional `unscheduled-treatment`, `plan-intelligence`, and `provider-utilization` views use `/api/reports`, leaving all report engines untouched.
- Report metadata supplies its actual interval, clinic timezone and generation timestamp. Plan-period figures are plans whose start date is in that period, with current status; unscheduled-treatment is a narrower current active-plan/pending-item subset that excludes a patient with **any booked appointment today or later**, even for another treatment. It is not a complete count of unbooked plan items.
- Doctor performance is appointment/visit/chair-time evidence plus source-formatted production and attributed collection in native currencies. It is not payroll, commission, live availability, net profit or a provider expense allocation. Missing duration/utilization evidence remains unknown. The DTO whitelists displayed fields and discards phone, arbitrary notes, commission and salary columns.
- The optional report readers return their complete result, not a paginated API. The UI labels its first ten returned rows and links the full report; these readers are never used for initial overview or polled. The new current-plan pulse is bounded independently.

### Privacy and concurrent ownership boundary

All private tasks are excluded in the hub-owned pulse SQL, including the signed-in owner's private tasks. The existing lab backlog reader (`lib/lab-backlog-db.ts:page_tasks`) can include the owner's private linked tasks and its DTO has no visibility marker per task. This pass deliberately withholds **all linked-task titles, assignees and counts** from the hub's lab detail and links to canonical HR; it does not alter the lab team's shared reader or infer which returned task is private. Shared accountability remains visible through the independently filtered task source. No payroll source is mounted.

`app/api/executive/route.ts` is still the finance team's existing server contract. Its current implementation authorizes before the financial read, but has no post-read principal recheck or explicit private/no-store response header. The hub uses no-store requests and account-keyed/abortable presentation; coordinating a server-side end-of-read principal check and response cache policy remains a concrete finance/permissions follow-up. No central finance/permission engine is changed here.

No migrations, schema edits, production data, financial mutations, patient uploads or AI/Dot features are part of this pass. See `docs/LEADERSHIP_COMPLETION_REVIEW.md` for evidence and remaining limits.
