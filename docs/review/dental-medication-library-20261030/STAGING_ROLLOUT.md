# خطوات ترقية الروشتات إلى الاستيجنج

هذه وثيقة تنفيذ مشروط، وليست سجل نشر. لا نشر أو تهيئة حسابات أو صلاحيات بمجرد دمج الكود.

## 1. تثبيت النسخة المركبة

- فرع المرشح: `feat/dental-prescription-templates-20261030`، PR497.
- المصدران: Rx المقبول `49268aee99d92eecef08621cccd032f399af4c32` وmain `6a6bdc0cc705874fd4ff6d0f0ddc3fdcd314e9e6`، بما فيه #499. التركيب merge عادي، بلا force-push.
- لا يُدمج فرع490 أو WORK أو فرع الشعار500. لا تدخل هجرة الترقيم0080 من تلك الفروع. تصحيح اختبار الاستعادة المشترك يُحفظ: provenance قراءة ملفات قبل الاتصال، والوجهة غير الفارغة تبقى بلا تغيير في البيانات والتدقيق والوثائق وسجل الهجرات وعناصر الكتالوج.
- أثبت SHA وشجرة Git النهائيين (`git rev-parse HEAD` و`git rev-parse HEAD^{tree}`)، ونتيجة CI الكاملة والمراجعة المستقلة على هذه الشجرة. نجاح المصدرين منفصلين أو merge-tree وحده لا يكفي.
- الاختبارات تشمل قبول0090 التاريخية على سلسلة Rx المعروفة، واستعادةSQL/fullarchive مع بيانات حجز فارغة وممتلئة. الاختبارات السلبية للإصدار المجهول والبصمة الخاطئة تبقى مستقلة؛ لا تعتبر0090 مجهولة عندما تكون موجودة في سلسلة المصدر الفعلية.

## 2. بوابة ميتاداتا الهدف — قبل تشغيل النسخة الجديدة

يشغّل المخوّل الاستعلام التالي بوصوله الحالي إلى staging فقط. لا حاجة لأي بيانات مرضى أو أسرار. لا تشغّل التطبيق للحصول على الدليل: startup قد ينفذ أعمال مخطط أخرى قبل حارس امتدادRx.

```sql
BEGIN READ ONLY;
SET LOCAL statement_timeout = '10s';
SET LOCAL lock_timeout = '2s';
SELECT version,name,checksum,adopted,applied_at
FROM public.schema_migrations WHERE version >= '0090' ORDER BY version;
SELECT table_name,column_name,udt_name,is_nullable,column_default
FROM information_schema.columns WHERE table_schema='public' AND (
 (table_name='booking_requests' AND column_name IN ('request_key','request_hash','preferences')) OR
 (table_name='prescriptions' AND column_name IN ('prescribing_doctor_name','prescribing_doctor_party_id')))
ORDER BY table_name,column_name;
SELECT t.relname AS table_name,i.indisunique,i.indisvalid,i.indisready,
 i.indnullsnotdistinct,i.indnkeyatts,i.indnatts,am.amname,
 pg_get_indexdef(i.indexrelid,1,true) AS index_key,
 pg_get_expr(i.indpred,i.indrelid) AS predicate
FROM pg_index i JOIN pg_class idx ON idx.oid=i.indexrelid
JOIN pg_class t ON t.oid=i.indrelid JOIN pg_namespace n ON n.oid=idx.relnamespace
JOIN pg_am am ON am.oid=idx.relam
WHERE n.nspname='public' AND idx.relname='booking_requests_request_key_idx';
ROLLBACK;
```

التوقع قبل الترقية:

- آخر سجل0090 باسم `booking_request_preferences` وبصمة `608eeee37b44a59cb4d26e915bd0b2610cf619103905be1fca0c2abe77c52e25` و`adopted=false`. يحتفظ التاريخ بـ`applied_at` الأصلي.
- `request_key` و`request_hash`: TEXT يقبل NULL، بلا default. `preferences`: JSONB لا يقبل NULL وdefault `'{}'::jsonb`.
- الفهرس فريد وصالح وجاهز، btree، مفتاح واحد `request_key` بشرط `IS NOT NULL`؛ دون أعمدة INCLUDE أو NULLS NOT DISTINCT.
- لا توجد قبل التطبيق أعمدة `prescribing_doctor_party_id` و`prescribing_doctor_name` ولا سجل0091/0092. أي اختلاف، بما فيه أثر Rx0090 القديمة أو رقم لاحق غير مراجع، يوقف الترقية للمراجعة. لا حذف أو تعديل سجل أو تبنّي checksum أو إعادة ترقيم تلقائية.

## 3. التحضير ثم نشر الاستيجنج فقط

1. بعد قبول الميتاداتا والمراجعة وCI، نسّق ناشرًا واحدًا وسجّل SHA الحالي ومعرف نشره. احفظ تحديثات main و#499؛ لا نشر متوازٍ من فرع آخر.
2. ضمن نافذة متفق عليها، أوقف الكتابات وخذ نسخة قاعدة ووثائق متسقة بالأدوات المعتمدة الحالية. تحقق من استعادتها إلى هدف معزول؛ لا تستعد فوق القاعدة الأصلية. احتفظ بأدلة النسخة وتاريخها خارج السجل العام.
3. انشر SHA المركب الموافق عليه على خدمة staging المحددة فقط. لا تعدّل أسرارًا أو صلاحيات أو ربط مالك أو منتجات دوائية لتجاوز أي بوابة. وثّق معرف النشر وSHA المشاهد فعليًا؛ لا تعتمد اسم الفرع وحده.
4. تحقق من بدء الخدمة والصحة، ثم أعد قراءة سجل الهجرات والكتالوج. يجب أن تبقى0090 وبياناتها وتاريخها كما هي، وتُضاف0091 و0092 فقط، بأعمدة nullable دون backfill.

## 4. قبول الاستيجنج ببيانات اصطناعية

- طبيب مصرح يكتب وصفة كاملة من زيارة اصطناعية، ثم تُحفظ ويُعاد فتحها وطباعتها من حساب مخول آخر: نفس معرف الوصفة والمريض والزيارة والمضمون واسم الطبيب المحفوظ، مع actor الحقيقي؛ لا نسخة مكررة.
- بعد إنهاء الزيارة، الاستقبال المخول يصل للوصفة المحفوظة ويطبعها فقط. لا إنشاء أو تعديل أو إبطال أو draft، ولا طباعة مفقودة/ملغاة/غير مطابقة للمريض. لا تضف grant حيًا لإجراء هذا الاختبار؛ استخدم حسابات الاختبار المصرح بها أو توقف لتوفيرها بالطريق المعتمد.
- اختبر رفض حذف selection أو amount أو confirmation من POST جديد، مع استمرار إعادة طباعة الوصفات القديمة دون هذه metadata. أبق critical409 وacknowledgment ونطاق المريض ومنع الطباعة الفارغة.
- راجع PDF/PNG: بدء قسم الدواء من اليسار، الوحدات والأرقام سليمة، العربية مستقلة RTL، اسم الطبيب الأصلي، بيانات المركز من الإعدادات، وسم المسودة المحايد وشريط void وعلامة staging محفوظة. لا توقيع أو اعتماد تلقائي.
- أثبت بقاء #499: قبول رصيد الإجازة الكسري وسلوك السنة المحددة وإعادة القراءة المعتمد. اختبر هيدر/فوتر الروشتة بإعدادات اصطناعية فقط، دون تغيير إعدادات حية.
- لا ادعاء بأن المالك يستطيع الإصدار باسم طبيب آخر أو بأن الجرعات تُحسب سريريًا: هذان المساران غير مكتملين تشغيليًا. المواد الأربع مساعدة تعبئة يدوية مع مراجعة الطبيب، لا اختيار مضاد أو جرعة أو مدة تلقائيًا.

## 5. الإيقاف والاستعادة والترقية التالية

عند فشل حارس الميتاداتا أو الهجرة أو فحص القبول: أوقف الترقية والكتابات، وسجّل الحالة الفعلية. لا تعدّل checksum ولا تحذف عمودًا أو صف هجرة لإخفاء الاختلاف. الهجرات معاملات منفصلة؛ لا تفترض rollback للحزمة كلها.

استرجاع backup إلى قاعدة معزولة يثبت قابلية استرجاع النسخة، وليس توافق binary قديم مع المخطط الجديد. لا ترجع الصورة القديمة وحدها تلقائيًا. أي cutover لاستعادة معزولة يحتاج الخطة المعتمدة والتحقق؛ وإذا حدثت كتابات بعد النسخة فلا تفقدها باستعادة صامتة.

لا إنتاج قبل قبول الاستيجنج على SHA ذاته واستكمال بوابة مراجعته. احتفظ بسجل أدلة: SHA/tree، رابطCI، نتيجة المراجعة، ميتاداتا قبل/بعد، معرف النشر والصحة، ونتائج الرحلة الاصطناعية دون معلومات مرضى.
