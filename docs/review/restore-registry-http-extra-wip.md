# Additional synthetic registry refusal HTTP witness — WIP

Based on `1ad9e1d433ac14ab90a3767dafe48cdd8e6ac1a6`. This test-only change adds a separate standalone HTTP witness and leaves production behavior unchanged. The archived-source positive control has a valid historical 0079 record; five separately reported mutants change 0079 name, checksum, adopted flag or timestamp, or add a 0090 record missing required fields. Each archive is derived from the real synthetic backup writer, with the manifest and recorded archive hashes recomputed; structural archive validation is required before HTTP.

A new synthetic source and one newly created target per case are identity-checked on the dedicated disposable CI PostgreSQL service. Source migrations run before inserting its synthetic rows. The positive control has its own exclusive initially empty target. Every refusal target holds a sentinel row, sequence and prior staged file. Each refusal runs the server with a new login checked not to be superuser or a member/owner of the `public` schema owner role; thus it cannot actually drop that target schema if the reset path is reached. The preserved staged file also detects an attempted reset path before the database call. The witness checks the HTTP refusal, target identity, public relation inventory, sentinel and sequence, previous staged file, unchanged source registry and archive bytes. This restricts schema ownership, not every possible database privilege or every kind of destructive SQL. It creates no connections to clinic databases and does not drop any databases or delete retained evidence. Synthetic target databases, roles, archives and before/after records remain for review for the lifetime of the CI service/runner only; they are not uploaded.

Local verification is limited to TypeScript syntax transpilation and two pure synthetic mutation/parser Vitest tests; no PostgreSQL, real standalone HTTP, full typecheck, build or CI has run for this change. The control and refusal cases are proposed executable tests, not successful HTTP evidence. Existing cases for missing ledger, non-writer 0079 spellings, infinity and absent footprints remain subject to separately reviewed compatibility policy; this witness does not assign their behavior.
