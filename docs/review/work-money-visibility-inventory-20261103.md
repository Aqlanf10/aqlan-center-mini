# رؤية الأسعار والمال في WORK — حصر وقاعدة إلزامية بقرار المالك

**المصدر:**
- **القرار الأول (#483، 6615071565):** أسعار تكلفة المختبر.
- **التوضيح الأحدث (#483، 6615124926)،** وهو الملزم: «يعني قصدي الاسعار والماليه مايشوفه الا من اعمل لهم صلاحية بذلك انا».

هذا القرار **لا** يخص صلاحيات التغيير بعد إرسال طلب المختبر، فتلك ما زالت معلّقة.

**الحالة:** حصر وقاعدة لخطة WORK. لا يغيّر سلوك المسارات القديمة الآن ولا يمنح أي حساب صلاحية. التطبيق الفعلي يتم في الشريحة الموحّدة لكل مسار.

## 1. القاعدة الإلزامية لكل شريحة قادمة
1. **منحة صريحة:** كل سعر أو مبلغ أو رصيد أو تكلفة أو ربح أو عمولة أو راتب أو قيد محاسبي لا يُعاد إلا لمن منحه المالك صراحة الصلاحية المالية المناسبة لنوعه (`finance.*` أو `hr.payroll.*` أو `reports.financial.view`). الدور الوظيفي أو دخول الوحدة أو `*.view` السريري لا يكفي.
2. **في الخادم:** المنع في API والوصول المباشر بالرابط، وفي البحث والتصدير والطباعة وأي رد. إخفاء الواجهة وحده لا يكفي.
3. **أحد شكلين واضحين:**
   - **الإسقاط:** حقول المال تُحذف من الرد بلا الصلاحية، وقائمة الحقول السريرية قائمة سماح؛
   - **الرفض الكامل:** حين يكون المورد ماليًا بطبيعته، كجدول الأسعار.
   - لا «قيم مطموسة» تكشف الشكل.
4. **الرؤية منفصلة عن التعديل:** رد الكتابة لا يعيد مبلغًا محفوظًا لمن لا يملك صلاحية رؤيته (نمط 70ب).
5. **الاختبارات الإلزامية:**
   - المخوّل؛
   - غير المخوّل (بما فيه من يملك الوحدة أو الدور)؛
   - سحب الصلاحية من جلسة قائمة؛
   - الوصول المباشر عبر API؛
   - عدم ظهور المبلغ في النص الكامل للرد.
6. **بلا منح تلقائي:** لا صلاحيات جديدة لأي حساب حقيقي، وقوالب البداية لا تتغير ضمنيًا.

## 2. ما طُبّق فعلًا في المسارات الموحّدة (الرأس `7f9697ca`)

| المسار | المال فيه | البوابة | الدليل |
|---|---|---|---|
| `GET /api/lab` | التكلفة والمبلغ الأساسي والسعر والالتزام والحسابات والترحيل | `finance.cost-prices.view` (إسقاط بقائمة سماح) | PG `lab-canonical-reads`، رحلة `canonical-lab-board-journey` |
| `POST /api/lab`، `PATCH` و`DELETE /api/lab/[id]` | الطلب في الرد | إسقاط بـ`finance.cost-prices.view`؛ حقول المال في الإنشاء مرفوضة | PG `lab-canonical-create` و`lab-canonical-orders` |
| `GET /api/lab/pricing` | أسعار التكلفة | **رفض كامل** بلا `finance.cost-prices.view` | PG `lab-canonical-pricing` (مع السحب)، رحلة `canonical-lab-pricing-journey` |
| كتابة الأسعار | المبالغ في الرد | `finance.lab-prices.edit`؛ المبالغ في الرد بـ`finance.cost-prices.view` فقط | المصدر نفسه |
| `GET /api/laboratories(/[id])` | عملة المختبر وحساباته | إسقاط بـ`finance.payables.record`؛ الكتابة مرفوضة | PG `lab-canonical-directory` |
| `GET /api/patients`، `/[id]`، `/[id]/arrival-panel`، `GET /api/visits` | الأرصدة | إسقاط بـ`finance.patient-ledger.view` (`patientDirectoryProjection.balances`) | حزم المرضى الموحّدة القائمة |
| `GET/POST /api/plans/proposals` | إجمالي المقترح | `finance.patient-ledger.view` | `canonical-proposals` |
| `GET /api/plan-templates` | أسعار الخدمات | `finance.service-prices.view` | حزم الخطط |
| `/api/shifts` | الصندوق والحركات | `finance.shifts.view` / `operate` (وتفاصيل `finance.payments.view` و`finance.expenses.view`) | حزم الورديات |
| `/api/ortho/[id]/followup-coverage`، وقرارات الفوترة | التغطية والفوترة | `finance.agreements.manage` / `finance.invoices.create` | حزم التقويم |

**مراجعة القراءات الموحّدة:** فحصتُ الوحدات الموحّدة لكل مسار `canonical-done` (101 طريقة) بحثًا عن حقول المال. كل ما يحمل مالًا مربوط بصلاحية مالية. قراءات التقويم (`/api/ortho`) سريرية فقط، والإشارات فيها كانت مطابقات لفظية لا مبالغ.

### نقاط انتباه: حاجة الخريطة لا تتضمن صلاحية مالية بينما المحتوى غالبًا مالي
تُحسم في شريحة كل منها بإسقاط أو رفض، وقد تحتاج تأكيد المالك لنوع الصلاحية:

| المسار | حاجة الخريطة الحالية | المطلوب عند النقل |
|---|---|---|
| `GET /api/executive` | لا شيء | الأرقام المالية بـ`finance.profits.view` أو `reports.financial.view` |
| `GET /api/finance/commissions` | لا شيء | العمولات بصلاحية مالية صريحة؛ عمولة الطبيب نفسه تحتاج قرارًا: هل يرى الطبيب عمولته؟ |
| `GET /api/parties` | لا شيء | أرصدة الجهات وحساباتها بصلاحية مالية؛ الاسم والتواصل دون مال |
| `GET /api/plans` | لا شيء | أسعار البنود وإجمالي الخطة بـ`finance.service-prices.view` أو `finance.patient-ledger.view` |
| `GET /api/settings/material-rates` | `settings.view` | أسعار المواد تكلفة: `finance.cost-prices.view` |
| `GET /api/report` و`GET /api/reports/daily-clinic` | `reports.operational.view` | أي إيراد أو تحصيل فيها بـ`reports.financial.view` |
| `GET /api/hr/reports` | `hr.reports.view` | الرواتب والمبالغ بصلاحية رواتب صريحة |

### نقاط عابرة
- **قارئ سجل التدقيق (`/api/audit`، قديم):** تفاصيل `lab_pricing.*` و`lab_order.create` و`lab_order.cancel` و`lab_order.delete` وغيرها تحمل مبالغ للمساءلة. عند نقله يجب أن يُسقطها بلا صلاحية مالية.
- **التصدير والطباعة** (`/api/export*` وقوالب PDF، وكلها قديمة): التصدير يتبع صلاحية رؤية المال نفسها.
- **قوالب البداية والكتالوج:** لا تُغيَّر ضمنيًا. أي اقتراح بتعديل التبعيات (مثل جعل `finance.lab-prices.edit` تستلزم `finance.cost-prices.view`) قرار مالك.

## 4. حدود هذا الحصر
- **المصدر:** مستخرج من الخريطة والمصدر بفحص آلي ثم مراجعة يدوية للحالات المشتبهة. لم يُختبر محتوى كل مسار قديم.
- **المسارات القديمة:** ما زالت تعمل بالأدوار لجلسات النظام القديم حتى القطع (M5). تغيير سلوكها الآن خارج النطاق، ويُحسم بنقلها.
