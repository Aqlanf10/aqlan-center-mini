# الشريحة 36 — قراءة خطط المريض وبنودها السريرية

الأساس المحلي `55aca0078c2fa5517fc8b752820f961214da833b` على WORK نفسه. هذه قراءة محددة داخل ترتيب ortho / ceph / plans في HANDOFF؛ ليست اكتمال وحدة الخطط أو نقل كتاباتها وتمويلها. أُثبت على التطبيق المبني قبل التنفيذ أن الحساب canonical المخوّل يسجّل الدخول، ثم يحصل على **401 بدل 200** لقراءة خططه.

العقد `GET /api/patients/[id]/plans` يحتاج `clinical.plans.view` ونطاق المريض معًا. أضيف تسجيل واحد إلى سجل القراءات، واستخدمت آلية `readCanonicalPatientRecord` القائمة دون تغيير إثبات السلطة أو منح صلاحية جديدة. `none` و`own` غير المرتبط يرفضان؛ المريض خارج النطاق والمفقود لهما الرد نفسه. المالك يقرأ الإسقاط السريري نفسه؛ المالية مستقلة، ولا تستنتج من مسمى الدور أو إعداد مالية الطبيب.

القارئ القديم يجلب الأقساط والدفعات والفواتير والاتفاقات قبل إسقاطها؛ وحتى `withoutPlanPayments` يحتفظ بالأسعار وإجماليات البنود. لذلك لم يُمرّر إلى القراءة السريرية. استعلامات القراءة الجديدة تختار حقولًا سريرية صريحة ولا تستعلم جداول المال. إجمالي أو سعر أو عملة تالفة لا تغيّر الإسقاط السريري، مثبت باختبار. جسم GET القديم وقراؤه وكتابه الماليون محفوظون دون تغيير.

تتضمن القراءة عنوان الخطة وحالتها وتواريخها وملاحظاتها والموافقة كما سُجلت، ثم الخدمة والتصنيف والسن والأسطح والكمية والحالة والملاحظات وطبيب البند وموضع الحالة ورقم الزيارة المستهدفة والجلسات. المنجز يُعد من `treatment_sessions` بحالة `done`، وفق المصدر القائم، وليس العداد القديم؛ لا قيمة افتراضية لهدف غائب ولا إجراء موافقة أو علاج أو فوترة. الروابط السريرية إلى حالات وزيارات المريض والجلسات تُفحص قبل العرض؛ الربط بمريض آخر يرفض النتيجة كلها.

حدود القراءة: أحدث **100 خطة** بترتيب تاريخ الإنشاء ثم المعرّف مع `hasMore` صريح؛ **256 بندًا للخطة، و2000 بند للنتيجة، و2 MiB** قبل تحميل النصوص. تجاوز حدود المحتوى يرفض، ولا يبتر البنود أو الملاحظات. كل القراءات على اتصال ولقطة RR READ ONLY واحدة، مع إثبات الصلاحية بعد انتظار السياج وإعادة فحص انتهاء الجلسة قبل النشر.

الواجهة داخل ملف المريض للقراءة فقط، بلا روابط إلى كاتب legacy أو أزرار موافقة أو مال. تمسح البيانات عند التحديث والخطأ والإخفاء وسحب المنحة، وتستبعد الرد المتأخر بعد إغلاق اللوحة. فُحصت لقطة اصطناعية بعرض 390px دون تمرير أفقي؛ الجلسات المنجزة 1 والهدف المسجل 3 ظاهران بعناوين منفصلة، والعداد القديم 99 والأرقام المالية لا تظهر.

النتائج المركزة النهائية حتى هذه المحطة: **45/45 PostgreSQL في 4 ملفات** (25 جديدة، و7 ملخص الاتفاق القديم، و13 جدولة/إعادة حجز)، **91/91 وحدة في 3 ملفات** (24 جديدة)، وحراس الخريطة والجرد **10/10**. النوع وlint المركز والبناء `CWHqDRPKDlYArK-XQq9f_` وpreflight وحارسا المال والأجسام ناجحة. **18 شاهدًا**: جسم GET القديم و16 ملفًا محميًا متطابقة، وسجل القراءات يتغير بتسجيل واحد محدد فقط.

محاولات غير ناجحة محفوظة بصدق: أول PG أخفق اختبار واحد عند إنشاء fixture بحالة `open` غير المسموحة؛ صُححت إلى `active` دون تغيير قيد المخطط، ثم نجحت المجموعة. أول استدعاء لحارسي المال والأجسام استخدم اسمي npm غير موجودين، فلم ينفذ فحصًا؛ أُعيد بالاسمين الفعليين `scan:money` و`ci:scan:body` ونجح. أول مولّد شاهد المطابقة تجاوز buffer القراءة الافتراضي لملف `lib/db.ts`؛ زيد حد أداة الإثبات فقط إلى 8 MiB ثم تطابقت الملفات، دون تغيير كود المنتج أو عتبة قبول.

الجرد بعد هذه القراءة: 383 مدخلًا، منها **55 canonical-done و289 existing**؛ الجرد الأوسع **NOT_READY**. هذه حالة تحويل مصدر، لا نسبة إنجاز ولا جاهزية تشغيل. لا هجرة أو تخصيص 0093، ولا تعديل تاريخ سريري أو حساب مالي أو بيانات حية.

حدود القبول السابقة محفوظة: مراجعة المصدر المستقلة لـ32–34 على `a7af0bde` لم تجد مانعًا في قراءاتها، لكنها مشروطة بكامل CI ولا تشمل نقل الأدوات الواسع. بوابة الجودة على ذلك الرأس نجحت بـ13534 وحدة، وPostgreSQL بـ4804 اختبارًا في 381 ملفًا مع الرحلات التشغيلية؛ HTTP والبوابة النهائية قيد المتابعة عند هذه المحطة. نتيجة ذلك الرأس لا تغطي 35 أو 36. عائق Docker هو HTTP 403 لفهارس Alpine أثناء تثبيت su-exec، ولم تنتج صورة WORK. إنشاء Draft PR مرفوض ولم ينفذ، ولم يُعد عبر مسار آخر.

[manifest المصدر والسجلات واللقطة](evidence/work-plans-clinical-20261101/manifest.json) يميز الفحوص المكتملة عن المعلقة. البصمات السابقة للأدوات و32–35 تحققت من التزاماتها التاريخية، وأضيف `sourceRevision` لئلا تُقرأ كبصمات للرأس المتغير.

اكتمل runtime للبناء النهائي: 737 trace و86 manifest و367 خريطة مصدر متاحة. هذا نطاق الإثبات المحدد؛ لا ادعاء غياب كود مبهم بلا خريطة. جميع الفحوص المحلية المعلنة لهذه الشريحة انتهت بنجاح، والقبول النهائي مرتبط بالرأس المنشور وCI والمراجعة المستقلة.
