# Administrative restore archive precheck — WIP review

This is a bounded fix and test checkpoint, not release or deployment approval. The prior administrative drill verified archive hashes and documents, then reset its dedicated target before `stagedRestore` inspected the historical 0079 registry. An internally contradictory 0079 archive with matching hashes could therefore cause a reset before being refused. The previous stage directory was also removed before archive verification.

The administrative path now parses, validates and checks the historic 0079 SQL contract before resetting the target or removing the prior stage. The integrity hash and parsed archive derive from the same opened compressed-file descriptor. Its gzip stream is hashed and decompressed in one pass into a private temporary tar, and the parsed result from that snapshot is passed to `stagedRestore`, which validates it again. No new arbitrary archive-size cap is introduced. On POSIX the newly created temporary tar name is unlinked while its descriptor stays open; on Windows its name remains until cleanup. A symlink to a regular source remains supported, while a FIFO is refused using nonblocking open and descriptor `fstat`.

A synthetic test was red before this change: a hash-valid archive containing an 0079-sensitive visit column without its historic registry record reached a mocked target connection and returned `restore-failed`. With the change it returns `archive-integrity-mismatch`, does not connect or issue a target query, and preserves a synthetic prior staged document. A second synthetic test changes the archive path at mocked connection time and verifies that the exact earlier parsed snapshot is passed to restoration. FIFO and ordinary-file symlink tests also pass. The six targeted unit suites passed 40/40; scoped ESLint had zero errors and two pre-existing warnings. A failed intermediate experiment using a FileHandle write stream was replaced and retested; it is not part of the final implementation.

**Limits:** The target connection was mocked in these unit tests; no real PostgreSQL target, built standalone server, or HTTP journey was exercised for this fix. The preserved document was a synthetic file in a newly created temporary test directory. Full typecheck, build, complete CI and independent release acceptance are not claimed. `archiveSnapshot` is a mutable `ParsedArchive` accepted by the internal `stagedRestore` API: the same-snapshot guarantee here is established for `runAdminRestoreDrill`, which keeps the reference local, not for an unrelated caller that shares and mutates its snapshot across awaits. The private temporary-name unlink guarantee is POSIX-specific; Windows retains the temporary filename until cleanup. Neither limitation is a proof of safety for other callers or environments.

All test inputs were synthetic. No patient or production data was accessed, no existing target or evidence directory was modified, and no merge, push or deployment was performed. The real standalone HTTP witness, independent review, final-head tests and the existing 0079 separation/recovery gates remain necessary.
