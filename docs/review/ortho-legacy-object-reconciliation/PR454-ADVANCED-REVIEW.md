# Source review of advanced PR454 — no merge

Reviewed `fbff0be738300d2df38430bb1e7f245e4c602685` against the originally authorized `1014a268afd0b477554c97f974b8961846cf69b8`. The two added commits are `2a1c5af0` (logging) and `fbff0be7` (0051 reconciliation). This is source review, not an independent rerun of that newer branch's tests. No changes were cherry-picked or merged; continuation ownership remains isolated.

1. **Blocking target mutation in report mode.** `referenceItems()` in `lib/ortho-legacy-reconciliation.ts` creates a target schema, changes search_path, and executes published migration SQL inside a savepoint. Rollback does not make the operation SELECT-only. Its foreign keys can touch referenced public parent catalogs and take locks. The CLI's “report only and writes nothing” claim is therefore incorrect for the requested boundary. The required reference belongs in an entirely separate synthetic database.
2. **Insufficient equivalence scope.** `catalogItems()` explicitly excludes owners/ACLs; it also does not establish complete collation/security/dependency equivalence. Thus an `exact` classification is not the requested full contract witness. Schema-prefix normalization does not fix this.
3. **Concurrent drift remains possible.** The relation/advisory locks do not protect function replacement/ACL changes or independent sequence changes. Rehashing immediately before COMMIT is a check, not exclusion of a change immediately afterwards. The exposed `onBeforeCommit` seam runs after the final rehash, which further limits what its drift tests establish.
4. **Live target surface is broader than authorized synthetic work.** `scripts/ortho-reconcile.ts` imports environment loading and connects through the application's pool; database-name comparison alone is not a Staging/Production identity gate. The continuation must not inherit this as a live mode.
5. **Diagnostics are narrower than raw exceptions but not fully pinned.** Logging has fixed categories and catches logger failures, but accepts any four-digit migration version and reads error message/code accessors. It does not meet the continuation's strictly pinned version/accessor treatment without additional changes.
6. **Useful direction, not approved live implementation.** Limiting reconciliation to 0051 and using the existing transactional audit table are relevant design ideas. However the audit event must explicitly distinguish catalog equivalence from historical execution, and retention/restore semantics need verification. COMMIT-acknowledgement uncertainty is not represented as a distinct outcome by that implementation.

These findings do not authorize modifying or closing PR454. Its later work remains separate. See `STAGING-DESIGN.md` for a narrower empty-0051-only proposal with explicit remaining evidence and permission requirements.
