هذه شريحة محددة لحالات تقويم قائمة مرتبطة صراحةً بحالة `clinical_cases` متخصصة في orthodontics. يظهر غياب الجسر كرفض صريح. أضيف فقط مسارا strategy وassessment، وترحيلَا0051 و0052 الأصليان، والمحرك المجمد2.1.0 ومحرراهما. لا0047 أو0053–55، ولا إنشاء حالات أو تفعيل علاج أو تثبيت أو تصدير أو منح صلاحيات اعتماد. جميع الحسابات مسودات غير معتمدة سريريًا.

## السلوك الناتج

- إدخال كل قياس مرة واحدة، وربطه بمجموعة مشتركة لتحليلات المساحة وBolton. اختيار عدة أسنان لتطبيق مصدر جلسة يحتاج تأكيدًا صريحًا؛ الحقول الأخرى تبقى دون تعديل. لا يُفترض صفر أو تاريخ اليوم أو هوية المسجل كمنفذ للفحص.
- حفظ إلحاقي مع سبب وهوية مسجل من الخادم، وإعادة فتح المراجعات، ومنع تجاوز رأس قديم. فقد رد الحفظ يُسوّى بنفس الأمر المجمد دون نسخة مكررة. رد خطة صحيح الشكل يخالف النص أو الروابط المرسلة لا يمحو المسودة.
- القفل يبدأ بالمريض في الكاتبين؛ الجلسة الحالية والحساب والصلاحيات وشواهد الوصول تُقرأ بعد انتظار القفل. هوية حالة التقويم مستقلة عن هوية الحالة السريرية. دمج المريض يغيّر الملكية الحالية مع حفظ recorded_patient_id والمحتوى والتسلسل وإعادة الطلب.
- بصمات ceph/history مبنية على إسقاطات حقول سريرية مسماة ذات إصدار؛ إضافة عمود nullable غير سريري لا تغيّرها. الملكية تتحقق منفصلة. نسخ ملاحظة يحتاج بصمة المحتوى الأصلية المطابقة، لا مجرد هوية مراجعة صحيحة.
- تسجيل0051/52 يرفض تعارض الاسم أو checksum أو adopted، والكائنات القديمة غير المسجلة حتى لو تشابه SQL. الفحص يسبق تخطي المسجل في CLI ويتكرر بعد BEGIN قبل DDL تحت القفل المشترك. لا adoption أو تعديل صامت لعقد قديم.

فروق الملفات المشتركة وتفويض الجذر المحدد في [coordination/README.md](coordination/README.md) و[الفرق](coordination/current-shared-contracts.patch.txt). هوية ومالية PatientOrtho ومساراتهما الحالية محفوظة. `session.ts` و`patient-access.ts` و`backup.ts` وترحيلات HR والـbaseline وملفات الاعتماديات لم تتغير؛ [manifest المصدر](source-manifest.json) يسجل البصمات.

اجتاز كود4a02 المجموعة الشاملة محليًا؛ CI ما زال قيد التنفيذ ولا يُدعى نجاحه الكامل. آخر دفعة التسليم تضيف الأدلة وتؤكد اختلاف الأرقام في اختبار المتصفح فقط؛ كود التطبيق لم يتغير منذ4a02. نجاحات الفروع أو الرؤوس السابقة لا تثبت رأسًا جديدًا. [manifest الأدلة](evidence-manifest.json) يسجل الأوامر والنتائج والبصمات، و[أوامر الإعادة](verification-commands.md) توضح البيئة الاصطناعية المعزولة.

صور strategy وassessment عند390/1280 محفوظة في evidence وفُحصت بصريًا. الحالة والموظف والقياسات جميعها اصطناعية. مواضع صور الحالات الخاصة فارغة؛ لم تُختلق صور أو بيانات مرجعية. لقطات الصفحة الكاملة تحتوي الترويسة/التنقل الثابتين القائمين، وليست دليل تصدير أو طباعة دراسة حالة.

السجلات الحمراء محفوظة: اختلاف أسماء التبويب على الهاتف، Chromium غير مضبوط في تشغيل محلي، فشل الشاهد السريري لزر القياس المعطّل ثم إصلاحه، فجوة سجل CLI قبل اعتماد حارسه، وتوقعات الاتحاد القديمة. `unit-full-final.txt` بدأ قبل تعديل مصدر العرض وأثناءه؛ لا يُقبل كشهادة رأس ثابت. تشغيل PostgreSQL الأول افتقد علامتي البيئة المؤقتة CATEGORY_HISTORY_CI_DISPOSABLE_FIXTURE وMANUAL_CASH_CI_DISPOSABLE_FIXTURE؛ رفضت أربع مجموعات البدء، كما كشف عقد الكشف القديم، وحمّل مشغل CLI قبل اكتمال تعديل السجل أثناء العمل. انتهى بـ2092 نجاحًا و5 فشل و94 متخطاة؛ ليس شاهد الرأس الحالي. تشغيل4a02 الجديد يستخدم مصادر ثابتة وإعداد CI المؤقت الصحيح على خادم مستقل.
