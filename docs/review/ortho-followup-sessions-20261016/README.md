# روابط جلسات الخطة في متابعة التقويم

الأساس:main `928bb7e5d140797c8654fc59016b3beb02acbb14`، بعدPR337 وPR336. الفرع الوحيد: `feat/ortho-followup-sessions-20261016`. أعاد الجذر تضييق الشريحة إلى فجوة المصنف الذي يعيدplannedVisitId دائمًا للمراجعة لغياب حقائق الجلسات والبنود. التوقيع الذري وربط شدّة اليوم موجودان ويُعاد استعمالهما دون إعادة بنائهما.

## السلوك الناتج

الموعد الدوري الذي تحمل زيارته المخططة جلسات معلّقة مرتبطة كلها ببنود تخص الحالة السريرية الصحيحة يظهر كمتابعة مؤكدة الغرض. يظهر بجواره «جلسات خطة مرتبطة بهذه الحالة؛ الحجز لا يثبت التنفيذ». الموعد الفعلي وتاريخه والطبيب يأتون من مصادرهم القائمة؛ لا تاريخ استحقاق مختلق كحجز، ولا اعتماد أو توقيع أو قبض من قراءة القائمة.

المسار المثبت هو appointments.planned_visit_id → planned_visits.id، مع تطابقplanned_visits.appointment_id عكسيًا، ثمtreatment_sessions.planned_visit_id → plan_items.case_id → clinical_cases.id → clinical_cases.ortho_case_id. معرّفclinical_cases مستقل عنortho_cases؛ الأمثلة تختبرهما بأرقام مختلفة عمدًا. plan_items.plan_id يجب أن يطابقplanned_visits.plan_id، ومريض الخطة والزيارة والحالتين واحد. الجلسات والبنود معلّقة، والخطة جارية، والزيارة السريرية إن وُجدت مطابقة وغير موقعة. الخطة المشتركة أو الطبيب أو اسم البند لا يثبت أيًا من هذه الروابط.

تُجمع الحقائق فيSELECT واحد؛ كل جلسة داخلة في الحكم، ولا تُحذف الجلسات المخالفة أو المكتملة لصنع نتيجة إيجابية. الزيارة المختلطة أو الروابط المفقودة/الأجنبية/المتناقضة، أو الحجز الذي لا يطابق الرابط العكسي، تبقى ظاهرة في قائمة المراجعة. لا إصلاح تلقائي ولا تحديث للروابط أو الحالات. لا تُعرض مبالغ الخطة أو سجلاتها الخام فيAPI؛ تخرج نتيجة التصنيف فقط.

يبقى غرض المتابعة شرطًا مستقلًا: خدمة متابعة دورية معرّفة، أوfollow_up قديم بلا خدمة متناقضة. مسارschedulePlannedVisit العام ينشئ موعدًا بلانوع/خدمة، لذلك لا يكفي بمفرده لتأكيد المتابعة الدورية؛ لا نستنتج أن بدء العلاج أو زيارة مختلطة «شدّة». طُرح هذا الحد للجذر للتوضيح، والعمل يحافظ على الشرط القائم دون افتراض سياسة جديدة.

## الحدود والتنسيق

التغيير المشترك فيlib/db.ts داخلorthoFollowupBoard وSELECT القراءة فقط. لم تتغيرrecordAdjustment أوwriteOrthoSessionInTx أوsignClinicalVisit أوlinkOrthoCasePlan أو كتّاب المال. لا مخطط أوmigration جديد، ولا حاجة لتسجيل رقم. [coordination.json](coordination.json) يقارن رأسيHR339 والمخزون338؛ تقاطع ملفات هذه الشريحة مع نطاقيهما صفر. لا دمج أوrebase أو نشر أو بيانات حية.

واجهة/مسودة الزيارة اليومية، إجراءات الأسلاك والإزالة،IPR، التثبيت، التصدير، بدء حالة جديدة، والكاتب المالي خارج هذه الشريحة. لا نسخة موازية من بيانات الأساس أو الزيارة. [مصفوفةO01–O52 والـ349 مطلبًا](requirements-matrix.json) محدثة علىmain المقروء مع أدلة جزئية محددة؛ جميع السيناريوهات الكاملة ما زالت غير مقبولة.
