# 0079 writer retirement: preservation test notes

This records a partial writer cut, not a completed 0079 separation. Fresh database migration and archive restoration are separate integration work. A historical table or row is never removed by this change.

The retired writer checks authorization, the command lock and exact actor/patient/case/request fingerprint first. A matching committed receipt is replayed; a matching historical rejection remains a rejection. An unknown command is refused before inserting either a decision or a refusal tombstone. A changed command using an old key remains a conflict. Status is a separate read and unavailable storage returns 503, not an invented rejection.

`__tests__/postgres/ortho-coverage-retired-writer.test.ts` explicitly installs the exact 0079 contract on a newly created, owned synthetic PostgreSQL fixture. It inserts historical success and rejection fixtures and checks exact replay, status, authority denial, changed-body conflict, concurrent unknown commands and unchanged historical rows/audit. Disabled storage guard yields 503 and preserves rows. `__tests__/ortho-followup-coverage-panel.test.tsx` includes a simulated React/journal 503 case; it confirms the saved command remains and is not acknowledged. It is not a built-browser result. A fresh DB actually lacking 0079 still needs an integrated end-to-end status test after migration retirement.

Existing creation tests must not simply be deleted, skipped, or weakened. Tests originally exercising historical creation should run against an isolated frozen historical writer and the exact 0079 migration, construct fixtures before the cut, and retain their transaction, authority, race, signed-proof, backup and immutable-guard assertions. Then test the resulting database against the retired writer and readers. In particular review `ortho-followup-coverage-concurrency`, `ortho-followup-coverage-restore`, `ortho-coverage-canonical-command`, `ortho-followup-command-recovery`, `ortho-explicit-followup-coverage`, canonical editor and the coverage browser journeys; tests expecting new writes cannot pass unchanged on retired behavior. Preserve all historical assertions as applicable and add explicit refusal checks. The existing 0079 migration and fixture fingerprints must remain unchanged. Do not claim the full suite passed based on this focused test.
