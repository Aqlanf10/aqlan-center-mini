# الشريحة 32 — الاستراتيجية المحفوظة للتقويم

الأساس `b014fe68799794066d11959f3d767ce0a3d7a05f` على فرع Claude WORK نفسه. هذه محطة مستقلة ضمن حزمة 32–34 المعتمدة، لا تحويل للوحدة كاملة. أثبت اختبار التطبيق المبني قبل الإصلاح أن الحساب canonical المخول يقرأ الحالة ثم يحصل على 401 بدل 200 لقراءة الاستراتيجية. الفجوة أعيد إنتاجها اصطناعيًا، وليست ادعاء حادثة إنتاج.

## عقد القراءة

`GET /api/ortho/[id]/strategy` يقبل معرف الحالة واختيار `revisionId` واحد فقط. القدرة `clinical.ortho.view` مع نطاق المرضى الحالي. اللقب الإداري لا يمنح الوصول. المالك يحتفظ بصلاحياته، لكن هذا العقد لا يفتح كتابة أو تمويلًا.

لقطة RR READ ONLY واحدة تشمل التحقق المركزي من الهوية والصلاحية، نطاق المريض، الجسر السريري المملوك، التاريخ الكامل وحالات الروابط الحالية. يُعاد التحقق بعد انتظار سياج دورة الهوية. المريض أو الحالة خارج النطاق يشبهان الغائب في 404. الجسر الغائب بلا تاريخ حالة صريحة؛ وجود تاريخ فقد جسره يرفض بدل إخفائه. لا تهيئة schema ولا إنشاء جسر.

يعاد استخدام مدقق schema 1 وتسلسل النسخ والإسقاط التاريخي الموجود. حدود القراءة 5000 مراجعة و8 MiB قبل تحميل التاريخ، واتحاد 128 معرف مشكلة/بند عبر كل نسخه؛ التجاوز يرفض صراحة ولا يبتر التاريخ. النص السريري الذي دوّنه الطبيب محفوظ كما هو. روابط بنود الخطة تتطلب `clinical.plans.view` على النسخة الحالية والمختارة تاريخيًا؛ عند غيابها لا تُرسل أسماء أو معرفات أو أعداد بنود أو اختيارات تحرير. لا تُقرأ أسماء حالية أجنبية لتحل محل النص التاريخي. لا أسعار أو أرصدة أو صور أو بيانات تمويل في الاستجابة.

الواجهة تعيد استخدام قارئ الاستراتيجية الحالي دون lifetime تحرير: فتح عند الطلب، اختيار النسخ، مسح القديم عند التحديث أو الإخفاء أو السحب، ومقاومة ردود متأخرة و15 ثانية مهلة قراءة. التحديث الدوري 30 ثانية وبالتركيز/الظهور. هذه قراءة محفوظة، لا إعادة حساب لنتيجة سريرية ولا إعادة فتح علاج منتهٍ. أجسام GET القديم وPOST ودوال المخزن القديمة لم تتغير؛ نوع اتصال قارئ التاريخ اتسع إلى واجهة query دون تغيير جسمه.
