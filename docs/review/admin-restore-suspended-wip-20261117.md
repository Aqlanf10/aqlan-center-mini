# Administrative restore drill suspended — WIP

The administrative drill previously removed its staged files and reset the target schema before the staged restore could reject a nonempty target. A declaration that the target is dedicated does not establish that it is empty or isolated. This temporary change keeps the existing archive, migration-provenance and target-identity preflight, then returns a fixed unavailable reason without constructing a restore client, changing database state, removing the prior stage, overwriting the prior drill state, or invoking staged restore. Valid configuration remains distinguishable from permission to execute. The settings UI reports the suspension and identifies a prior ready result as historical, without altering that record.

This disables every administrative drill, including a correctly isolated empty target, until a separate reviewed design can establish the required isolation. It is a compatibility change. The HTTP route still performs its existing read-only authentication before calling the disabled drill; the no-connection assertion applies to the drill's restore client, not to authentication.

The combined review branch also refuses the explicit `allowNonEmptyTarget` option before archive or target access, including the full-restore CLI flag, and temporarily refuses every raw SQL restore CLI invocation. Calls to staged restore with the option absent or false still follow the existing path: they may connect to check the target, and its table count does not prove isolation or prevent concurrent writes. The offsite drill is a separate path; this change does not establish its safety. The full and offsite CLIs on this parent can also reject their own `DATABASE_URL` through the target-alias collision check; that usability issue is separate. DNS aliases, connection races, and historical application pools are not resolved here. Existing standalone HTTP and raw SQL tests that require successful restoration remain unchanged and conflict with the temporary suspension. No deletion of evidence, local PostgreSQL connection, deployment, or build was performed for this change. Tests use synthetic archives and mocked clients.
