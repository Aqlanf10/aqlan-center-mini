# Proposed slice65 — explicit case/plan link context and chooser

Design only. Follows the64 command; no new financial writer or migration. Default clinical case GET stays minimal. An explicit independently admitted plan-link context should expose only current same-patient plan identity/title/status, case observation, and paged eligible same-patient plan choices. Keep native active/retention and non-cancelled target rules. Require ortho view/edit and plan view/edit plus current patient scope in one fenced RR READ ONLY snapshot. Do not expose total, currency, installments, agreement approval, funding, invoices or other patients. Fail closed on corrupt old parent and invalid/oversized titles. Independent read scope must not grant a command.

Use keyset pages with honest next cursor and separately resolve current selected plan; no truncation disguised as all choices. No duplicate query values or caller-selected scope. Revalidate capabilities/session and source ownership; a response arriving after withdrawal, hidden tab or patient/actor change cannot restore a selection.

The UI should be a separate small explicit control in the existing clinical case detail, preserving its identity and old lifecycle editor. Reuse the existing observed-version/pending-review policy: synchronous send latch, minimal session marker, no automatic PATCH replay, refresh and explicit new intention after uncertainty. Explain that current-state reading is not an exact request receipt. Keep pending ownership mounted across periodic detail/list refresh or integrate with the existing parent owner registry. Do not promise reload recovery when storage is unavailable. No clinical text in the marker, no guessed owner identity.

Acceptance: actual pre-change explicit GET400, scoped own/all/owner positives and none/independent-grant negatives, strict projection/bounds/pagination, coherent concurrent changes and expiry, no writes/DDL in read, actual390px chooser link/unlink, no hidden financial details in DOM/network, late responses, polling, revocation, lost response, storage failure, command-vs-old-observation conflict, legacy UI regression.65 adds no method count. Implementation begins only after64 bounded command evidence is frozen.
