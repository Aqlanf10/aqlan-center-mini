# Financial Action Trace

One row per financial button: UI → API → domain function → DB → audit → accounting (derived journal) → reports.

| Action | UI | API | Domain function | DB (writes) | Audit | Accounting (derived) | Reports |
|---|---|---|---|---|---|---|---|
| **Create invoice (visit sign)** | Visit «مراجعة وإنهاء الزيارة» | `POST /api/visits/:id/clinical` `{action:"sign"}` | `signClinicalVisit` (row lock `signed_at IS NULL`) | `invoices`, `invoice_items`, `visits.signed_at`, sessions, lab orders | visit sign | `invoiceEntry`: Dr AR / Cr Revenue (+ Dr Discount) — **raw currency, see F-05** | Ledger, debts, commissions, Executive billing |
| **Create manual invoice** | Patient ledger «فاتورة جديدة» | `POST /api/invoices` | `checkInvoiceAuthority` → `createInvoice` | `invoices`, `invoice_items` | `invoice.create` (+ price overrides) | `invoiceEntry` | same |
| **Correct invoice** | Ledger «تصحيح» (admin) | `POST /api/invoices/:id/correct` | `correctInvoice` (cancel + reissue) | new invoice; old status `cancelled` | `invoice.correct` (sensitive) | old entry disappears (cancelled), new entry appears | same |
| **Cancel invoice** | Ledger | `PATCH /api/invoices/:id` | `setInvoiceStatus` | `invoices.status` | `invoice.status` (sensitive) | entry removed (`cancelled`) | same |
| **Collect payment** | «تحصيل» / checkout | `POST /api/payments` (Idempotency-Key) | `recordPayment` (shift lock, target, hash replay) | `payments` (append-only) | `payment.create` | `paymentEntry`: Dr Cash/Bank[c] / Cr AR (base) | Ledger, shift expected, finance summary, commissions (collected) |
| **Refund** | Ledger «ردّ» | `POST /api/payments` `{kind:"refund", reversalOfId}` | `recordPayment` (Σ refunds ≤ original, inherits target) | `payments` | `payment.refund` (sensitive) | Dr AR / Cr Cash | same |
| **Plan installment** | Plan «قسط» | `POST /api/plans/:id/installments` | `recordPlanInstallment` (idempotent, FIN-1) | `invoices` + `payments` | `plan.installment` | invoice + payment entries | same |
| **Open / close shift** | Cash desk | `/api/shifts` | `openShift` / `closeShift` (blind count) | `cashier_shifts` (expected, difference stored) | shift open / close | `cashDifferenceEntry` (Cash vs 5961) | Z report |
| **Operating expense** | «سند صرف» (no party) | `POST /api/expenses` | `recordExpense` | `expenses` | `expense.create` | `expenseEntry`: Dr Expense / Cr Cash | finance summary `expenses` |
| **Pay supplier/lab bill** | Party page «سداد» (`PayBillForm`) | `POST /api/expenses` `{payableId}` | `recordExpenseInTx` (snapshot, `exceeds_payable`) | `expenses` + snapshot columns | `expense.create` | Dr AP / Cr Cash (no expense) | party statement, finance summary `expenses` |
| **Pay legacy (opening) debt** | Party page «سداد» on a «رصيد افتتاحي» row | `POST /api/expenses` `{payableId}` | same | same | same | Dr AP / Cr Cash | **finance summary `openingSettlements`** (not expenses) |
| **Supplier advance** | «سند صرف» above the balance | `POST /api/expenses` `{prepaymentReason}` | `recordExpenseInTx` (admin + reason) | `expenses` (note «دفعة مقدمة») | `expense.prepayment` (sensitive) | Dr AP (debit balance) / Cr Cash | statement `unlinkedPaidMinor` |
| **Grouped lab settlement** | Lab accounting «تسوية مجمعة» | `POST /api/finance/lab-accounting` | `settleLabOrdersBatch` | `expenses` + `expense_payable_allocations` | lab settle | Dr AP / Cr Cash | lab reconciliation |
| **Void voucher** | Voucher «إبطال» | `DELETE`/`POST /api/expenses/:id/void` | `voidExpense` (negative reversal row) | `expenses` | `expense.void` (sensitive) | reversal entry | all of the above net |
| **Lab cost → payable** | Lab order cost | `/api/lab`, `/api/lab/:id/accounting` | `createLabOrder` / `updateLabOrderAccounting` | `lab_orders`, `payables` | lab accounting | `payableEntry`: Dr lab expense / Cr AP | lab board, statement |
| **Cancel lab order** | Lab «إلغاء» | `PATCH /api/lab/:id` | `setLabOrderStatus` (unpaid payable removed; paid payable kept) | `lab_orders`, `payables` | `lab_order.status` | entry removed / kept | statement |
| **Delete lab order (permanent)** | Lab «حذف» (admin) | `DELETE /api/lab/:id` `{reason}` — **reason mandatory** | `deleteLabOrder` (refused when settled; **reason_required**) | deletes order and its unpaid payable | `lab_order.delete` (snapshot + reason) | entry removed | — |
| **Stock purchase** | Inventory «إدخال شراء» (+ supplier) | `POST /api/inventory/:id/movements` | `createInventoryMovement` (movement + payable in one transaction) | `inventory_movements`, `payables` | `inventory.move` | `payableEntry` (Dr supplier expense / Cr AP) | valuation, statement |
| **Stock return / consumption / adjust** | Inventory | same | same | `inventory_movements` | `inventory.move` | none (periodic expensing, F-12) | valuation |
| **Patient opening balance** | Patient file «رصيد افتتاحي» / `/finance/opening` | `/api/opening-balances` | `setPatientOpeningBalance` (history) | `patient_opening_balances(+_history)` | `opening_balance.set/clear` (sensitive) | `openingBalanceEntry`: Dr AR / Cr 3101 (**YER only**, F-06) | ledger, debts |
| **Opening payable (legacy supplier/lab debt)** | `/finance/opening` → «ديون المعامل والموردين السابقة» | `POST /api/party-openings` `{kind:"payable"}` (admin, reason) | `createPartyOpeningPayable` (party lock, duplicate guard) | `payables` (`source_type='opening'`) | `party_opening.create` (sensitive, in transaction) | `openingPayableEntry`: **Dr 3101 / Cr AP** — no expense | statement, suppliers report, Executive `payableByCurrency` |
| **Correct opening payable** | same, «تصحيح القيمة» | `PATCH /api/party-openings` `{action:"adjust"}` | `adjustPartyOpeningPayable` (≥ settled) | `payable_adjustments` (append-only) | `party_opening.adjust` (from → to, reason) | opening entry re-derived at the corrected value | same |
| **Opening advance** | same, «رصيدٌ مقدَّم لنا» | `POST /api/party-openings` `{kind:"advance"}` | `createPartyOpeningAdvance` | `party_opening_advances` | `party_advance.create` | `openingAdvanceEntry`: Dr AP / Cr 3101 | statement `openingAdvanceMinor`, Executive |
| **Void opening advance** | same, «إلغاء بسبب» | `PATCH /api/party-openings` `{action:"void_advance"}` | `voidPartyOpeningAdvance` | `party_opening_advances.voided_*` | `party_advance.void` | entry removed | same |
| **Post manual journal** | `/finance/accounting` | `POST /api/accounting` | `createManualEntry` (balanced, period lock) | `journal_manual(_lines)` | `journal.manual` (sensitive) | as entered | trial balance |
| **FX revaluation** | `/finance/fx` | `POST /api/finance/fx` | `postRevaluation` | `journal_manual` | `fx.revalue` (sensitive) | Cash[c] vs 5951 | income statement |
| **Doctor commission payout** | Commissions «صرف» | `POST /api/expenses` (party kind `doctor`) | `recordExpense` | `expenses` | `expense.create` | Dr Expense (5301) / Cr Cash | commission report (paid vs earned, per currency) |

**Not applicable:** there is no "unpost" of document entries. The journal is derived, so a document's cancellation or void is its unposting. Period locks (`isPeriodLocked`) block manual entries and opening balances dated in a locked period.
