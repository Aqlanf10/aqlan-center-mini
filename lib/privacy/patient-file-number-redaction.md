# File-number privacy gate: not mounted

This offline helper does not change the numbering pilot, AI settings, routes, or any outbound behavior. It prepares bounded matching and the trusted classification contract; it is not an approval to send clinical text.

An untyped `R-01500` can be a receipt, a patient file, or both. Giving all financial prefixes an exception would allow a valid owner-chosen series to disclose patients. Hiding everything with any finance-like prefix is also not reliable classification. The future server adapter must resolve exact normalized candidates from authenticated, local, authoritative records and make a patient match win a namespace collision. An explicit patient file label, an exact trusted historical file ID, or a legacy P/Arabic file form is always masked. An unrelated confirmed receipt is left intact. Candidates and lookup results are local-only, never telemetry.

The helper bounds text to 4,000 code units, historical facts and ambiguous identifiers to 64 distinct entries, and identifiers to 64 units; refusal returns no outbound text and never silently truncates. It preserves original text outside matched spans while handling standard Arabic and Persian digits, Latin case, fullwidth presentation, directional control marks, and typographic hyphens. The caller must use a consistent normalized candidate lookup, account for historic/custom unlabelled formats outside the new grammar, and keep existing name/address/phone guards. Without trusted historical coverage and a complete decision for each ambiguity, keep the external route closed for this feature. A caller's claim that a value is a receipt is not proof. No list of the clinic's identifiers should be copied, logged, exported, or passed to providers.

## Separate numbering design target

The SQL fence pilot is intentionally monotone at or above 7000. That is not the final supported owner choice. Design an explicit **new, unused series** with a separately chosen display start such as 1500, without resetting the existing P series or the shared physical allocation high-water mark. An independently persisted per-series display offset/high-water could keep one increasing physical allocator while enabling a new unused namespace. Require verified “unused” proof, unique/normalized comparison, restart and recovery state for every series, and a replay-safe owner confirmation. Reusing an old prefix or creating a prefix/sequence that overlaps financial identifiers requires a separately verified policy; the privacy gate must cope with legitimate collisions, not silently prohibit a valid choice.
